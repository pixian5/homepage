# Safari 扩展自动注册（自愈）（2026-11-04 01:30）

版本：26.7.6 → **26.7.7**。响应需求：扩展「查不到」时能否改为自动注册。

**要解决的问题**：26.7.5 复核时发现构建后扩展登记丢失（`pluginkit` 查不到），只能人工发现再手动 `pluginkit -a`。触发场景不止构建一种——Safari 运行中重装、系统重启后登记丢失、Safari 更新后消失，都会让新标签页回落 `favorites://`，而用户毫无感知。

---

## 一、方案：launchd 定时自愈（沿用 25.9.4 签名体检的成熟模式）

| 文件 | 作用 |
|---|---|
| `scripts/safari-extension-register.sh` | 核心脚本（幂等）：查登记 → 未登记则 `pluginkit -a` → 轮询复验最多 10 秒。`--check` 参数只查不注册（退出码 0=在册 / 3=丢失），供外部监控用 |
| `scripts/setup-safari-extension-register.sh` | 安装/卸载 launchd 任务：`install` / `uninstall` / `status` / `run-now` / `logs` |

launchd 任务（`com.aeroluna.homepage.safari-extension-register`）：

- **每小时**检查一次 + **每次登录/加载**时检查；
- 扩展在册时什么都不做（幂等，开销可忽略）；
- 注册失败只写日志（`~/Library/Logs/homepage-extension-register.*.log`），下个周期自动重试。

### 构建脚本同步改造

`build-macos.command` 原有的内联注册块（注册 + 5 秒轮询 + 失败仅告警）替换为调用核心脚本，语义不变（构建不因注册失败而中断），但告警信息改为指向自愈任务——即使构建时注册没成功，**一小时内 launchd 会自动补上**。

## 二、验证（全部实测）

| 场景 | 结果 |
|---|---|
| 幂等：扩展在册时执行 | ✅ 「扩展在册，无需注册」直接成功 |
| `--check`：在册/丢失 | ✅ 退出码 0 / 3 |
| **模拟丢失自愈**：`pluginkit -r` 移除 → 跑脚本 | ✅ 检测到未登记 → 自动注册 → `pluginkit -m` 重新查到（26.7.6） |
| launchd 安装 | ✅ `launchctl list` 出现 `com.aeroluna.homepage.safari-extension-register`（退出码 0） |
| install 时立即执行一次 | ✅ 在册跳过 |
| 完整构建走新链路 | ✅ `[build] Safari extension registered` |
| 测试 / Biome / 版本 | ✅ 275/275、26.7.7 四处一致 |

## 三、说明

- launchd 任务已在本机安装启用（`install`）；不想要时 `bash scripts/setup-safari-extension-register.sh uninstall`；
- 换机迁移：新机器跑一次构建后执行 `install` 即可（与签名体检任务同一套路）；
- 该任务只针对**扩展登记**丢失；若 `.app` 本身被删除（登记和文件都没了），脚本会报「找不到 .appex」并退出，不会误操作。
