# Safari 扩展“消失”的根因与构建期注册校验（2026-10-26 20:06）

版本：26.1.6 → **26.1.8**。

## 一、现象与原因

用户反馈 Safari 扩展突然没了：新标签页回落 `favorites://`，`pluginkit` 查不到扩展。

排查结果：

| 检查 | 状态 |
|---|---|
| `/Applications/我的首页 Safari.app` | 存在，版本 26.1.6 |
| `.appex` 文件 | 存在，签名正常 |
| `pluginkit -m -p com.apple.Safari.web-extension` | **没有 homepage** |
| Safari 进程 | 运行中 |

**根因**：构建脚本会用 `rm -rf` 删除旧的 `/Applications` 应用再复制新的。
如果此时 **Safari 正在运行**，`pluginkit` 不会重新登记被打包替换的 `.appex`，
Safari 也就看不到扩展。这在本轮多次「构建 → 装 → 继续改」的过程中被反复触发。

## 二、修复

`scripts/build-macos.command` 在安装、配置新标签页选中之后，新增：

1. 显式执行 `pluginkit -a <appex>`；
2. 最多等 5 秒轮询确认扩展已登记；
3. 已登记则打印成功；未登记则输出明确警告和手动修复命令，**但不让构建失败**
   （Safari 运行中注册可能延迟生效，失败不应阻断构建）。

同时把 `scripts/build-macos.command` 同步为 `dist/build-macos.command`。

## 三、实测

| 场景 | 结果 |
|---|---|
| Safari 未运行 → 构建 | ✅ `[build] Safari extension registered` |
| **Safari 运行中 → 构建**（真实故障场景） | ✅ 扩展仍登记为 26.1.8，新标签页正常 |
| 构建后打开新标签页 | ✅ `safari-web-extension://.../newtab.html` |
| 单元测试 | 203/203 |
| `npm run check` | 通过 |

## 四、如果再次遇到扩展消失

```bash
# 1. 退出 Safari
osascript -e 'tell application "Safari" to quit'

# 2. 手动注册
pluginkit -a "/Applications/我的首页 Safari.app/Contents/PlugIns/我的首页 Safari Extension.appex"

# 3. 重新打开 Safari
open -a Safari
```

正常情况下现在不需要手动做这一步。
