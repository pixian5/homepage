# 27.2.3：Manifest 内容脚本按需注入收敛、Safari 安装注册顺序修复与原生安装验收

## 问题与实现

1. **三端 Manifest 移除静态 `<all_urls>` `content_scripts`（`manifest.chrome.json`、`manifest.firefox.json`、`manifest.safari.json`）**：
   - 删除三端清单中的 `"content_scripts"` 配置块，保留 `"permissions"`（含 `scripting`、`tabs`、`activeTab`）与 `"host_permissions": ["<all_urls>"]`，消除普通网页加载时的预注入开销。
   - 生成产物 `dist/chrome/manifest.json`、`dist/firefox/manifest.json`、`dist/safari/manifest.json` 与 `/Applications/我的首页 Safari.app/Contents/PlugIns/我的首页 Safari Extension.appex/Contents/Resources/manifest.json` 均已核验为 `"version": "27.2.3"` 且不再含 `"content_scripts"`。

2. **加固 `src/popup.js` 跨浏览器按需动态注入兼容性**：
   - 新增统一扩展异步调用适配器 `callExtensionApi` 及注入辅助函数 `executeScriptingFiles`、`executeTabsScript`，并重构 `sendRuntimeMessage`、`sendTabMessage`、`openBookmarkSidebar` 与 `showToastInTab`：
     - 优先使用回调形态读取 `runtime.lastError`；若 API 同时返回 Promise，或因 Firefox/Safari `browser.*` Promise-only 封装（如 `tabs.sendMessage` 第 3 参数类型校验或 `scripting.executeScript` 参数数量校验）同步抛错，自动回退为无尾随回调的单/双参数调用并接管 Promise，避免未捕获拒绝。
     - 以 `typeof document !== "undefined"` 守卫顶层 `init()` 自动执行，方便 Node 单测直调导出函数验证。
   - 新增 `tests/manifest-content-scripts.test.js`（8 项单测），覆盖三端 Manifest 权限与字段收敛、Chrome 回调按需注入、Firefox/Safari Promise-only 回退、`tabs.executeScript` 兜底、以及受限页注入失败如实返回 `false`。

3. **发现并根治 Safari 安装脚本 `pluginkit` 注册顺序缺陷（`scripts/build-macos.command`、`scripts/safari-extension-register.sh`）**：
   - **首次安装复现问题**：执行 `NO_PAUSE=1 bash dist/build-macos.command --install` 后做只读验收时，`pluginkit -m -v -i com.aeroluna.homepage.safari.extension` 返回 `(no matches)`，`bash scripts/safari-extension-register.sh --check` 退出码 3。
   - **根因定位**：`xcodebuild` 阶段会把构建目录产物注册到 LaunchServices/PlugInKit；原 `build-macos.command` 在清理构建产物**之前**调用 `safari-extension-register.sh`，而原 `is_registered()` 仅按扩展 ID 字符串匹配而不核验路径，导致其被构建目录残留记录欺骗并跳过注册；随后 `lsregister -u` 与 `prune_safari_build_products` 注销并删除构建产物，使 `/Applications/我的首页 Safari.app` 内扩展处于未登记状态。
   - **修复方案**：
     - `scripts/safari-extension-register.sh`：`is_registered()` 改为通过 `pluginkit -m -v -p com.apple.Safari.web-extension` 同时匹配 `${EXT_ID}` 与正式路径 `${APPEX_PATH}`；注册前先执行 `lsregister -f "${APP_PATH}"` 刷新正式 App LaunchServices 索引再调用 `pluginkit -a "${APPEX_PATH}"`。
     - `scripts/build-macos.command`：将 `lsregister -u "${APP_PATH}"` 与 `prune_safari_build_products` 提前至拷贝 `/Applications` 之后、`clean-safari-homepage-registrations.mjs` 与 `safari-extension-register.sh` 之前执行。
     - `tests/safe-build.test.js`：补充注册顺序与路径匹配防回归断言。
