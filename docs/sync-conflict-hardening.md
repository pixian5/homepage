# 多设备同步冲突加固

## 修复背景

真实双设备 HTTP 同步测试确认了四类问题：旧数据在不同设备分别修改标题和 URL 时会丢字段、相同远端重复合并仍被视为有效变更、错误的未来时间戳会永久压制正常编辑、固定 60 天墓碑会让长期离线设备复活已删除节点。

## 字段时钟迁移

- 新建普通书签同时初始化 `titleUpdatedAt` 与 `urlUpdatedAt`。
- 旧节点首次编辑前，先用编辑前的 `updatedAt` 补齐缺失字段时钟。
- 只推进实际变化字段的时钟，未变化字段保留旧基线。
- 编辑弹窗、文件夹重命名、设置页重命名、后台自动补标题和导入 URL 规范化使用同一写入规则。
- 本地修改清空旧 `updatedBy`，同步投影时写入当前设备 ID。

这样，A 修改标题、B 修改 URL 时，两个字段分别按自己的时钟裁决，不再使用整个节点的时间误判未变化字段。

## 单调逻辑时间

本地编辑、移动和删除使用 `nextSyncTimestamp()`：结果至少等于本机当前时间，并严格大于节点已经观察到的所有相关时钟。即使远端设备曾写入 2100 年等异常时间，本地下一次操作仍可推进到更大的逻辑时间，不会永久失去修改能力。

逻辑时间用于冲突排序，不代表真实发生时间；界面不得把它当作可信的审计时间展示。

## 无变化合并

合并前后分别生成固定 `docId`、revision 和 writtenAt 的同步投影，通过内容哈希比较用户数据。只有投影内容实际改变时才返回 `stats.applied = true`。远端 revision 和同步状态仍由同步引擎单独记录，不再为了元数据变化反复保存首页数据、创建安全快照或触发渲染。

## 墓碑保留

当前协议没有设备成员列表和逐设备删除确认，因此无法证明某条删除已经被所有可能离线的设备观察。墓碑改为永久保留，避免任何离线时长下的旧节点复活。

代价是大量长期删除会增加同步文档体积。将来只有在实现以下协议后才能安全恢复垃圾回收：

1. 为同步文档维护明确的设备成员集合。
2. 每台设备记录已处理的远端 revision 或删除水位。
3. 仅当所有有效设备都确认越过某条墓碑后才清除。
4. 对已退役设备提供显式移除流程，不能依赖时间自动猜测。

## 验证场景

- 两端基于同一 ETag 并发新增，412 后拉取、合并、重试并最终收敛。
- A 修改标题、B 修改 URL，两个字段均保留。
- 相同远端重复合并返回 `applied = false`。
- 接收未来时钟后，本地编辑和删除仍能胜出。
- 删除 61 天后，旧离线节点仍不能复活。
- 网络失败后重试成功，幂等键不重复增加 revision。
- 测试结束后使用备份恢复隔离云端，规范化哈希与基线一致。

## 真实公网双端验收（2026-08-10）

在 `sf.sbbz.tech` 上保留生产同步端口 `58443`，另建隔离测试端口 `58444`。测试服务使用独立的 systemd 单元、低权限用户、数据目录、Token 和 Caddy 反向代理，测试期间所有请求只指向 `https://sf.sbbz.tech:58444`，不写入生产端点。

浏览器 A 使用独立 Profile 的 Google Chrome for Testing 加载 Chrome 23.8 产物，浏览器 B 使用独立 Profile 的 Firefox Developer Edition 加载 Firefox 23.8 产物。正式版 Chrome 151 已忽略命令行 `--load-extension`，因此自动化验收使用官方 Chrome for Testing；用户默认 Chrome Profile 未被修改。

真实浏览器与公网服务完成以下检查：

- 两端均从 revision 1 拉取同一基线，并发新增时第二端收到 HTTP 412，合并重试后推进到 revision 3。
- 两端都确认新增节点并集完整，节点总数为 3。
- A 修改标题、B 修改 URL，第二次 HTTP 412 合并重试后推进到 revision 5，两个字段均保留。
- 两端重复合并均为无变化；未来时钟后的本地编辑可恢复；过期墓碑仍阻止旧离线节点复活。
- Chrome 与 Firefox 的扩展本地存储在测试前后分别计算 SHA-256，恢复后哈希与各自备份完全一致。
- 云端测试数据恢复到基线后为 revision 6；忽略 revision 的规范化 SHA-256 前后均为 `2b3d3c8ad05f3567643fba2e96a43307a52c6dcf37b5716212d7e446a7e30e9e`。
- 测试端点和生产端点在无 Token 时均返回 HTTP 401；测试服务继续保留，服务器临时上传文件已清理。
