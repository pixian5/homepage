# 「同步间隔=关闭」时打开页面也不拉取，导致别的设备改了看不到（2026-11-03 16:45）

## 现象

在 Chrome 里把背景改成渐变，Safari 和火狐**一点变化都没有**。

## 取证

### 服务端是对的

`data/homepage-sync-state.json`（revision 88，16:06:37 由 Chrome 写入）：

```
backgroundType           : 'gradient'
backgroundGradient       : 'linear-gradient(120deg, #1d2a3b, #0b0f14)'
settingsClock.backgroundType = { updatedAt: 1793693195892, updatedBy: dev_d867…（Chrome） }
```

### Safari 根本没去拉

```
本地 backgroundType : 'bing'        ← 还是旧的
本地 _syncMeta.revision : 84
lastRemoteRevision : 85
lastPullAt : 16:05:57               ← Chrome 16:06:37 推送之后，再没拉过
syncInterval : 'off'
```

`lastPullAt` 停在 Chrome 推送**之前**，说明它不是「拉到了没应用」，而是**压根没发起请求**。

## 根因：`off` 把「首拉」也一起关掉了

初始化同步的代码原本是：

```js
if (interval !== "off") {
  const pull = await pullNow("init");
  ...
}
```

而 `startSyncInterval()` 在 `off` 时直接 `stopSyncInterval()` 返回。
两者一叠加，`off` 的实际语义变成：**除手动点「立即同步」和本地改动外，永远不访问服务器**。

于是别的设备改了背景/设置，本机开着页面也永远不知道——看起来就是「没同步」。

## 修法（两处）

### 1. 打开页面一律拉一次

```js
// 「同步间隔 = 关闭」只表示不做周期轮询，不代表打开页面也不看云端。
const pull = await pullNow("init");
if (pull?.needPush) await pushNow("init_need_push");
```

远端没变时 `pullNow` 会走 26.5.2 的短路（`unchanged`），直接返回——
不合并、不 render、不碰壁纸。所以这次「无条件拉」不会带来之前那种「没改动却重刷壁纸」的问题。

### 2. 切回标签页时补拉一次（60 秒节流）

```js
document.addEventListener("visibilitychange", () => {
  if (document.visibilityState !== "visible") return;
  ...60 秒内不重复...
  void pullNow("visible");
});
```

作用：标签页一直开着、期间别的设备改了东西，切回来就能看到，不必手动刷新。
仍然遵守节流与短路，不会变成高频轮询。

## 语义澄清（写在这里免得又混）

| 设置 | 含义 |
|---|---|
| 同步间隔 = 关闭 | 不做**周期轮询**；打开页面/切回页面仍会各拉一次 |
| 同步间隔 = 5 分钟 | 额外每 5 分钟轮询一次（页面可见时） |

## 验证

安装后打开 Safari，实测：

```
backgroundType : gradient
lastPullAt     : 2026-11-03 16:43:27
lastRemoteRevision : 88
```

渐变设置**自己就同步过来了**，不需要手动点「立即同步」。

回归：`node --test` 258 项全过；`npm run check` 85 个文件无告警。
