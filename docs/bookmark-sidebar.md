# 扩展书签菜单与网页侧栏

从 23.0 开始，点击扩展图标时显示固定 280px 的紧凑菜单。鼠标移到“添加书签”后，全部分组和嵌套文件夹以覆盖式子菜单逐层显示，不再改变扩展弹窗宽度；点击“在左侧栏显示所有书签”或“在右侧栏显示所有书签”会分别打开本程序自己的网页侧栏。

构建默认只安装 Safari 应用，不自动启动；需要手动验证宿主应用时显式设置 `SAFARI_LAUNCH_AFTER_BUILD=1`。

书签侧栏由 `js/bookmark-sidebar.js` 作为内容脚本注入当前网页，左右各显示一份本程序书签，右侧栏提供关闭按钮，底部文件夹按钮可筛选当前栏的书签。书签数据从弹窗通过运行时消息传入，点击书签后由后台根据本程序的打开方式设置创建或更新标签页。

从 23.1 开始，侧栏书签显示本程序保存的上传/远程图标；没有显式图标时依次尝试站点 favicon、公共 favicon 服务，全部失败后回退为彩色首字母图标。

从 23.3 开始，“全部”是唯一数据根目录，ID 固定为 `grp_all`。它的 `nodes` 可以按任意顺序混排普通书签和真实文件夹；首页左侧不再保存独立分组，只过滤显示 `grp_all.nodes` 中的根级文件夹。左侧的新增、重命名、删除与排序都会直接修改这些真实文件夹，点击左侧文件夹则直接展示其 `children`。

旧版普通分组会在加载时先生成本地备份，再转换为“全部”下的真实文件夹，同时为旧分组写入同步墓碑，避免旧设备把双重分组结构带回来。迁移完成后 `groups` 只保留 `grp_all`，不再存在代理文件夹或 `linkedGroupId`。导入、备份恢复、弹窗保存、网页侧栏和服务器同步都使用同一棵书签树。

从 23.4 开始，每个书签或文件夹只能存在于一个父位置。导入与数据修复按“全部”的显示顺序保留第一个有效位置并清除重复或循环引用；同步按节点的位置时钟选择唯一父目录，同索引冲突再使用稳定字段排序，避免跨设备移动后同时出现在多个目录。

从 23.6 开始，可将右侧书签图标直接拖到左侧文件夹。该操作是移动：节点会先从原父容器移除，再加入目标文件夹，不会复制书签；文件夹拖放同时阻止自身包含和祖先循环。

从 24.5 开始，扩展弹窗底部的“所有书签”按 `groups.nodes` 和 `folder.children` 的原始顺序递归显示分组、文件夹和书签。文件夹使用可展开树节点，书签保留在所属文件夹内，不再被平铺或按标题重排；已删除/清理节点会被忽略，异常循环只截断当前分支。点击树中的书签仍由后台按打开方式设置处理。

从 24.6 开始，扩展弹窗树中的书签条目只显示标题，不显示路径和 URL；文件夹层级与点击打开行为保持不变。

从 24.7 开始，扩展弹窗中的文件夹默认收起；“添加书签”菜单改为自身区域内的流式布局，嵌套文件夹在菜单内缩进显示，不再使用固定悬浮层覆盖“所有书签”区域。

从 24.8 开始，点击“添加书签”主菜单可在自身区域内展开或收起，并通过 `aria-expanded` 反映当前状态；点击具体文件夹时不会误关闭主菜单。

从 25.0 开始，添加书签菜单不再因获得焦点或鼠标悬停自动展开；只有明确点击主菜单才会显示文件夹，嵌套文件夹也只有点击右侧箭头才会展开，避免鼠标上下移动造成菜单重叠或内容错乱。

从 25.1 开始，“添加书签”展开后会显示“全部”根目录下的直属文件夹；“全部”仅作为导航根节点默认展开，真实文件夹仍默认收起，点击文件夹名称保存到该文件夹，点击箭头逐级展开子文件夹。

从 25.2 开始，“添加书签”入口使用独立按钮控制弹窗菜单，避免 Safari 将外层容器点击误判为弹窗外部点击；展开后稳定显示“默认”“新分组”等所有直属文件夹。

从 25.3 开始，弹窗底部“所有书签”不再显示内部虚拟根目录“全部”，直接显示其下的文件夹和书签；文件夹仍按树形结构默认收起，可逐级展开。

从 25.4 开始，弹窗书签树仅允许纵向滚动；深层文件夹缩进不会再生成横向滚动条，过长标题仍以省略号显示。

从 25.5 开始，弹窗宽度从 280px 提升到 560px，顶部菜单与书签树同步填充可用宽度。

实现不调用 Chrome、Firefox 或 Safari 的原生 bookmarks API。受浏览器内部页面权限限制时，侧栏可能无法注入，但弹窗仍可正常显示并保存书签。
