# 浏览器测试与发布经验

## 分层验证

1. `npm test`：Node 单元、HTTP 集成、同步冲突、恢复和脚本测试。
2. `npm run check`：Biome 格式和静态检查。
3. `npm run test:browser-smoke -- chrome`：Chrome 页面脚本、设置、增删、刷新持久化。
4. `npm run test:browser-smoke -- firefox`：Firefox Developer Edition 未签名扩展加载和同等冒烟。
5. `bash scripts/build-macos.command`：macOS Safari 宿主完整链路。

## CI 门禁

- CI 必须先安装依赖，再运行 Biome 和全量测试。
- 构建前执行 `bash -n` 检查 shell 脚本；JavaScript 使用 `node --check`。
- 构建后检查 `dist/chrome.zip`、`dist/firefox.zip`、`dist/safari.zip` 存在且 `unzip -tq` 通过。
- Firefox 冒烟使用 Developer Edition、Nightly 或 Beta；普通 release 版通常不能加载未签名 XPI。
- Safari 宿主签名和安装属于 macOS 专项门禁，不能由 Linux CI 的扩展包构建替代。

## E2E 浏览器进程泄漏（2026-11-04 事故）

- Playwright 启动的 Chromium 即便 `--headless=new` 无头模式，也会在 macOS 菜单栏注册"使用 Chromium 打开搜索功能"状态项（放大镜图标）。测试脚本退出未 `browser.close()` → 孤儿进程（父进程号变 1）每个挂一个图标，堆积成排。
- 排查：系统事件枚举各进程 menu bar 2~6 找图标归属；`ps -axo pid,ppid,lstart,command | grep "Google Chrome for Testing" | grep -vE 'Helper|--type='` 找孤儿主进程。
- 清扫：`pkill -f "homepage-pwa-e2e"` + 删 `/var/folders/.../T/homepage-pwa-e2e.*` 临时目录（2026-11-04 一次泄漏 7 个进程、97 MB）。
- 预防：所有端到端脚本必须 try/finally close；启动前先 pkill 清残留。详见 docs/20261104-1237-菜单栏放大镜图标堆积排查-GLM-5.3.md。

## 发布纪律

- 修改代码或文档后按项目规则递增版本，并同步 `VERSION`、package、lockfile 和三端 manifest。
- 使用 `SKIP_BUMP=1` 重复构建，避免验证过程再次改变版本。
- 发布前检查 `git diff --check`、工作区状态和最近提交。
- 失败日志要保留；不要只根据“命令退出成功”推断浏览器行为正确。
