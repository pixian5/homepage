# 27.2.5：Safari 注册自动启用修复与后台书签写入同步时钟对齐

## 问题与实现

1. **修复 Safari 扩展首次注册后未自动启用（缺少 `+` 标志）（`scripts/safari-extension-register.sh`）**：
   - 在 `pluginkit -a "${APPEX_PATH}"` 登记且轮询确认 `is_registered` 成功后，立即执行 `pluginkit -e use -i "${EXT_ID}" >/dev/null 2>&1 || true`。
   - 效果：每次全新覆盖安装或自愈重注册后，扩展即处于已登记且已启用（`+`）状态，无需手工追加启用命令；已有登记记录则不强制改写用户开关。
   - 在 `tests/safe-build.test.js` 补充 `pluginkit -e use -i` 防回归断言。

2. **修复后台网页侧栏加书签路径的同步时钟与异常兜底（`src/js/background.js`）**：
   - 从 `./sync_policy.js` 导入 `nextSyncTimestamp`（已在 `scripts/firefox-modules.json` 的 `background` 拓扑中）。
   - 抽取纯函数 `addBookmarkToFolderInData(data, { folderId, url, title, deviceId, now = Date.now() })`：
     - 校验 `folderId` 与 `http/https` 协议 URL，并验证目标容器存在且非非文件夹节点；
     - 使用 `nextSyncTimestamp(now, data.lastUpdated, container.updatedAt)` 生成严格单调逻辑时钟 `ts`，同步更新 `node.updatedAt`/`node.updatedBy`、容器 `updatedAt`/`updatedBy`、`data._syncMeta.placementClock[node.id]` 与 `data.lastUpdated`。
   - 在 `homepage_add_bookmark_to_folder` 消息监听器中增加 `chrome.runtime?.lastError` 读/写校验及 `getOrCreateDeviceId()` `.catch()` 兜底，防止异常时 `sendResponse` 通道悬空。
