## 关 SIP/Gatekeeper 能否免签名（实测证伪，版本 25.9.5）

- 用户问：新电脑 SIP 与 Gatekeeper 都关掉，是不是不用签名就能用。
- **实测发现本机 SIP 已经是 disabled**（`csrutil status`）→ 用户设想的「双关」条件本机已满足，可直接验证，无需真去关。
- 重跑探针矩阵（SIP 关 + Gatekeeper 关）：adhoc+沙箱 → **exit=133 仍被杀**；adhoc+沙箱+App Group → 同样 133；adhoc 无 entitlement → 正常；完全不签名 → 正常。
  → **关 SIP 和 Gatekeeper 都不解除签名强制。** 后两项能跑只是因为没沙箱，而 Safari 的 .appex 强制沙箱，不能推广。
- 机制要点（别再混淆三道门禁）：
  - Gatekeeper(`spctl`) 只管「下载应用首次打开」评估；
  - SIP(`csrutil`) 只管系统路径保护/task_for_pid/调试注入；
  - **AMFI 才管代码签名与 entitlement 强制**，且分两层：内核 `AMFI.kext`（受限 entitlement，**即使关 SIP 也绕不过**）+ 用户态 `amfid`（需 boot-args `amfi_get_out_of_my_way=1`）。
  - **关 SIP 只是让你有资格设 boot-args 关 AMFI，本身不关 AMFI。**
- 本机 `nvram boot-args` 未设置 → AMFI 未关；`amfid` 有 2 个进程在跑。
- 就算全关还剩两坎：Safari .appex 强制沙箱；App Group 需 Team ID（adhoc 无 Team ID）。
  注意假象：无沙箱进程能直接写 group container 目录，不代表沙箱内扩展能访问。
- 结论：不划算。签名免费且已自动化（launchd），关 SIP 是拿整机安全边界换零成本的东西。
- 已提醒用户开回 SIP（Recovery 里 `csrutil enable`）与 Gatekeeper（`sudo spctl --master-enable`）。
- 产出 `docs/20261008-2115-关SIP与Gatekeeper能否免签名-GPT-6.md`，索引已登记，git 已推送。
- 清理注意：探针会往真实 App Group 容器写 `probe.txt`，**测完必须删**（本次已清理，homepage-data.json 未受影响）。

## Safari 出现两个「我的首页」扩展：真因与修复（版本 25.9.6）

- **真因不是陈旧注册残留**，而是 **Safari 实际加载的是构建产物目录里那份 .app，不是 /Applications 的正式版**。
  实测进程路径 = `dist/safari-app/build/Build/Products/Release/我的首页 Safari.app/Contents/PlugIns/...`。
  危害：续签更新了 /Applications，Safari 却仍跑构建目录旧副本 → 7 天到期后照样失效。
- **排查教训（务必记住）**：查 plist 别用 `plutil -p | grep`。
  我早先据此误判有 `(PSTNW3UN4R)`/`(UNSIGNED)` 残留，实际那是**别的扩展**的团队 ID。
  正确做法：`plistlib.loads` 后按 key 判断 + 递归搜索值，本项目实测命中数为 0。
- Safari 27 的扩展数据在 `~/Library/Containers/com.apple.Safari/Data/Library/Safari/WebExtensions/Extensions.plist`
  （**不是** `~/Library/Safari/Extensions/`，那个目录已不存在）。
- **原 `lsregister -u "${APP_PATH}"` 注销源路径不够**，Safari 照样加载。必须物理删除构建产物。
- 修复：新增 `prune_safari_build_products`（在 `scripts/lib/safari-signing.sh`），

- **核心认知：签名证书 ≠ 配置文件**。证书（Apple Development, WY97WQFBKC）**1 年**有效，到 2027-08-04；
  profile 只 7 天。7 天瓶颈只属于**免费 Apple ID**。
- 探针矩阵（SIP disabled + spctl assessments disabled 状态下实测，exit=133 即 SIGKILL/AMFI 杀）：
  - A Apple Development + 沙箱+App Group + 无 profile → **133**
  - B adhoc + 沙箱+App Group → **133**
  - C Apple Development + 空 entitlements + 无 profile → 存活
  - D Apple Development + 沙箱+App Group + **有 profile 的 .app bundle** → 存活，读到 36685 字节
  - E Apple Development + **仅 App Sandbox** + 无 profile → **133**
  - F Apple Development + 仅 App Group（无沙箱）+ 无 profile → 存活
- **结论**：触发 AMFI 杀进程的是 `com.apple.security.app-sandbox`（受限 entitlement 需 profile 授权），
  **不是** App Group，也不是"没签名"。A 组有真证书真签名照样死，C 组同样签名 entitlements 空就活。
- Safari 扩展躲不开：宿主与扩展的 entitlements 都是 app-sandbox=true，两端都必须带 profile。

- 三条出路：① 现状免费+自动续期（0 成本，7 天）；② 付费+Development profile（1 年）；
  ③ 付费+**Developer ID + 公证 → 完全没有 profile**，Mac 第三方 app 标准做法。
