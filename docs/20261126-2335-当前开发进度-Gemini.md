# 27.3.1：修复历史固化写盘回滚、存储监听批事件与跨端 API 兼容

## 问题与实现

1. **修复 `history-manager.js` 历史固化写盘失败未回滚与容器时钟遗漏**：
   - 修改 `src/js/history-manager.js` 的 `addHistoryToShortcuts`，落盘前备份 `data.backups`、`targetGroup` 放置列表及 `updatedAt`/`updatedBy` 并触发 `touchPlacementContainer`（已在 `src/js/app.js` 注入）；若 `persistData()` 返回 `{ ok: false }`，精确移除新增节点并还原数组（同时兼容测试桩的原地引用修改与 setter）、容器时钟及备份队列、跳过图标抓取并提示 `error.saveQuota`；
   - `addHistoryToShortcuts` / `addHistoryToDefaultGroup` 返回保存布尔值，`openAddToGroupModal` 仅在保存成功时关闭弹窗。
2. **修复 `storage-listener.js` 批事件漏重载与 `bind()` 重绑定失效**：
   - 移除 `handleExtensionChanges` 命中 `syncKeys` 时的提前 `return`，避免单次 `storage.onChanged` 批量写入同时含同步键和 `homepage_data` 时跳过数据重载；
   - 在 `bind()` 调用 `dispose()` 后重置 `disposed = false`，恢复 `dispose() → bind()` 重新订阅能力。
3. **统一 `shared-utils.js`、`history-manager.js`、`bing-wallpaper.js` 与 `visit-history.js` 跨端 API 适配**：
   - 将 `shared-utils.js` 的 `storageGet` / `storageSet`、`history-manager.js` 的 `fetchBrowserHistory`、`bing-wallpaper.js` 的 `fetchViaBackground` 与 `visit-history.js` 的 `initVisitTrackingInBackground` 统一接入 `callExtensionApi(getChromeApi(), ...)`，兼容 Chrome 回调（自动消费 `runtime.lastError`）与 Firefox / Safari Promise-only 运行时。
4. **补充回归单元测试**：
   - 在 `tests/history-manager.test.js`、`tests/storage-listener.test.js`、`tests/bing-wallpaper.test.js` 与 `tests/visit-history.test.js` 新增 Promise-only、批事件、重绑定及写失败回滚用例，单测增至 623 项。
