## 一、同步引擎自动配对与退役熔断（`src/js/sync_engine.js`）

### 自动配对

- `getTransportConfig()` 读取 `settings.syncDeviceSecret` / `syncDeviceSecretUrl`（凭据绑定签发时的服务器地址，换服务器自动失效）。
- 新增导出 `ensureDevicePairing()`：同步开启 + 配置了 Master Token + 本地无有效凭据时，自动 `httpPairDevice` 签发设备独立凭据，写入 settings 并经 `_saveLocal` 持久化（落盘失败回滚内存，防"用了没存的凭据"）；并发去重（`_pairInFlight`）；配对失败静默降级 Bearer，不阻断同步。
- 设备名按 UserAgent 友好生成（Chrome / Firefox / Edge / Safari 扩展 / 未命名设备）。
- `getTransportAuth()`：有凭据且服务器未变 → 请求带 `Device <id>:<secret>`；否则回退 Bearer。pull / push / confirm 三个传输点全部接入。
- 触发点：`pullNow` 与 `pushNowImpl` 起始处自动补配对；设置面板「测试服务」成功后也调用（经 app.js 注入），随后刷新协同设备仪表盘——新配对设备立刻可见。

### 退役熔断（403 device_retired）

- `markDeviceRetired()`：`_status.status = "device_retired"`、`lastError = "设备已被管理员注销 (403)"`，并**立即停止周期轮询与防抖推送**（防高频空转）。
- pull / push 检测到 `device_retired` 即熔断返回；**失败不进 outbox 重试队列**（退役重试永远 403）；`flushOutbox` 加退役守卫。
- 设置面板状态行新增 `device_retired` → 红色「本设备已被注销，同步已停止」。
- **凭据失配自愈**：Device 凭据收到 401（服务器重建/换库）→ 自动清除本地凭据 → 下一轮同步用 Master Token 重新配对恢复。

### 发现并修复的真实缺陷（If-Match × 占位状态）

测试先行暴露：自动配对建立的「只有设备表、doc 为 null」占位状态，撞上客户端遗留的**旧服务器 etag**（If-Match）时，服务端 `state` 非空但 etag 不匹配 → 412；而占位状态无 doc，412 响应带不回 `remote.doc`，客户端重试耗尽**永远写不进新库**。双侧修复：

- 服务端：If-Match 只与**真实文档**比较（`state?.doc` 存在才校验），占位状态等价云端无数据；
- 客户端：`no_remote` 时清空 `lastRemoteEtag`（旧 etag 无意义）。

已固化为回归测试（独立空库实例 + 陈旧 If-Match 首写必须 200）。

## 三、墓碑回收常态化脚本（`scripts/run-tombstone-reclaim.sh`）

- bash 3.2 兼容（有意不用 `set -u`，规避空数组 unbound 坑）、零外部依赖（curl + node 原生 JSON 解析）。
- 流程：`GET /health`（墓碑/设备/可回收计数）→ `GET /v1/sync/devices`（每台设备的 epoch/revision 确认进度与退役状态——回收在等谁一目了然）→ `POST /v1/sync/reclaim {dryRun:true}`（候选详情 + epoch）→ `--force` 且有候选时 `{dryRun:false, confirm:"RECLAIM"}` 真正回收。
- 退出码约定：0 成功（含无候选）｜1 参数错误｜2 不可达｜3 鉴权失败｜4 回收失败。
- **踩坑记录**：首版把响应体经命令替换捕获（`BODY=$(http_get ...)`），函数内设置的全局 `STATUS` 在子 shell 里赋值传不回父进程——重构为响应体/状态码均走全局变量。
- 已真实冒烟全场景（dry-run / force / 复核归零 / 错 Token exit 3 / 不可达 exit 2）并配 3 项自动化测试。
