# 27.2.4：同步本地落盘失败原子回滚保护与 `content-toast` 重入幂等修复

## 问题与实现

1. **修复 `src/js/sync_engine.js` 本地写盘失败时的内存与冲突状态裂脑缺陷**：
   - 新增内部辅助函数 `persistMergedLocalState(nextState)`：严格先执行 `_saveLocal(nextState)`，仅当落盘返回空错误且未抛出异常时才调用 `_setData(nextState)`；若写盘返回错误或抛异常，保留原有内存 `data` 引用不篡改。
   - 新增内部辅助函数 `applyConflictLocalState(nextState, targetDocId, onMergedStats)`：在冲突解决（`"remote"` 与 `"merge"`）流程中，先执行 `_createSafety()` 与 `persistMergedLocalState(nextState)`，仅在落盘成功后才切换 `_status.docId`、清空 `_pendingConflictRemote`、删除 `conflictRemoteDocId`/`conflictLocalDocId` 并回调 `_onMerged`；落盘失败时维持 `_status.status = "need_setup"` 与完整冲突上下文以便重试。
   - 更新 `applyRemoteDoc`：改用 `persistMergedLocalState`，写盘失败或抛异常时设置 `_status.status = "error"`、`_status.lastError` 并返回 `{ ok: false, reason: "local_write_failed", error }`，不推进 `_status.lastRemoteRevision`、不回调 `_onMerged`、不向服务端发送 confirm 请求。
   - 更新 `pushNowImpl` 预拉取逻辑：由原先仅拦截 `doc_conflict` 改为拦截一切 `!pulled.ok`，避免预拉取合并或本地落盘失败时继续向远端发送 `PUT` 覆盖。

2. **修复 `src/js/content-toast.js` 按需重复注入词法重声明问题**：
   - 将全脚本及顶层 `const TOAST_ID`、`FONT_STACK`、`TOAST_STYLE_PROPS` 全部收口进 IIFE `(() => { if (window.__homepageToastInjected) return; window.__homepageToastInjected = true; ... })();`，确保同一标签页多次按需注入不会触发 `SyntaxError` 且监听器仅注册一次。
