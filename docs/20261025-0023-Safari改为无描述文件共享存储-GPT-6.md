# Safari 改为无描述文件共享存储（方案 B，2026-10-25 00:23）

版本：25.9.9 → **26.0.0**（跨大版本：存储位置与签名权限都变了，不复用旧逻辑）。

## 背景

前一轮文档记录了 macOS 27 上的硬限制：

- 带 App Sandbox 或 App Group 的 `.app` / `.appex`，**没有内嵌描述文件就会被 launchd/AMFI 直接 SIGKILL**；
- 因此 2026-10-08「去掉描述文件也能跑」的结论在 macOS 27 上失效；
- App Group 兜底文件自 2026-08-14 起就没再更新。

用户选择**方案 B：改无沙箱共享文件**——放弃 App Group，改用普通文件路径，两端都不再需要描述文件，
也就没有 7 天续期。

## 最终落地的形态

| 项 | 决定 |
|----|------|
| 共享文件 | `~/Library/Application Support/我的首页/homepage-data.json` |
| 宿主 App | 签**空 entitlement**（不启用沙箱）。带沙箱又无 profile 会被杀 |
| 扩展 `.appex` | **必须保留沙箱**（实测去掉后 `pluginkit` 不再登记扩展），只加共享目录例外 |
| 扩展的目录例外 | `com.apple.security.temporary-exception.files.home-relative-path.read-write` = `/Library/Application Support/我的首页/`（**必须以 `/` 开头**） |
| 描述文件 | 两端都不内嵌，也不申请 |
| 签名方式 | Xcode 只编译不签名（`CODE_SIGNING_ALLOWED=NO`），随后脚本用 Apple Development 身份手工签 |
| 版本 | 26.0.0 |

### 为什么扩展必须保留沙箱

这是本轮踩到的关键坑：把 `.appex` 也签成无沙箱后，`pluginkit -m` 里完全看不到扩展，
Safari 新标签页回落到 `favorites://`。恢复 `app-sandbox` 后立即恢复注册。
所以「无沙箱」只适用于宿主 App，不能套到扩展上。

### 为什么例外路径要写绝对形式

第一次写的是 `Library/Application Support/我的首页/`（无前导 `/`），签名写入成功但
运行时 `storage_failed`。改成 `/Library/Application Support/我的首页/` 后写入正常。

### 为什么 Swift 侧要用 getpwuid

沙箱里 `FileManager.default.homeDirectoryForCurrentUser` 返回的是
`~/Library/Containers/com.aeroluna.homepage.safari.extension/Data`，不是真实用户目录，
写入会落到容器里（实测确实生成了容器内文件）。改用 `getpwuid(getuid())->pw_dir`
取真实主目录，例外路径才生效。

## 代价与限制

- 失去 App Sandbox 安全边界（仅宿主 App；扩展仍有沙箱并按目录限定）。
- 不能上架 App Store。项目定位是自用开发测试版，可接受。
- 共享文件是明文 JSON，任何本机进程都能读；与旧 App Group 的可见性差别不大。
- 首次切换会自动迁移旧 App Group 文件（仅当新路径不存在时），不覆盖已有新数据。

## 回滚

旧的带描述文件版本仍可在 `.test-backups/safari-noprofile-20261008/我的首页 Safari.app` 找到，
但那版描述文件已于 2026-10-15 过期，在 macOS 27 上会被 SIGKILL，**不建议回滚**。
要回到 App Group 方案，需要在 Xcode 登录 Apple ID、恢复 profile，并把本轮的 entitlements
与 Swift 模板改回去。
