## 发现一 [P1] 保存失败回滚失效 + 最近分组添加后不切回 — modal-manager.js:312 / :517 / :299

**根因（接线语义错误）**：`app.js` 注入的 `getState: () => ({ data, openFolderId, activeGroupId })` **每次调用返回新建的快照对象**；modal-manager 内三处写操作都落在这个临时对象上，**从未回传**。注入的 `setState` 在模块内零调用（已 grep 确认）。

三个失效写点：

1. `state.data = snapshot`（modal-manager.js:312，新增路径；:517，编辑路径）——旧代码是 `data = snapshot` 直接赋值 `app.js` 闭包变量（本次 diff 删除侧可见），搬迁后语义丢失。`persistData()` 失败（存储配额超限等）时，节点已通过引用写入真实数据（`state.data.nodes[node.id] = node` 生效），但回滚不生效 → **界面显示保存成功，刷新后改动消失**，内存与存储不一致。
2. `state.activeGroupId = targetGroup.id`（modal-manager.js:299）——**正常路径**的行为回归：旧版在「最近」分组添加书签成功后会切到目标分组显示新书签，现在停留在最近分组。**每次都触发，无需失败条件**。

**修复方向**：三处改走 `setState({ data: snapshot })` / `setState({ activeGroupId })`，或让 `getState` 返回带 getter/setter 的存取器对象。

**测试为何没拦住**：modal-manager 测试全部用 mock 元素覆盖纯逻辑（Enter 绑定、默认按钮查找），未覆盖保存完整路径。修复时应补「`persistData` 失败后内存回滚」「最近分组添加后切换」两个用例。

## 发现二 [P1] 自定义背景上传被压缩成 128×128 — app.js:2215 + settings-controller.js:931

`readFileAsDataUrl` 被整体重定向到 `compressImageFileToDataUrl(file)`（默认 `maxDimension=128`，输出 WebP）。图标上传用 128 合理（本轮有意为之），但**设置面板的自定义背景上传走同一个函数**——用户上传的全屏背景图会被缩到 128px，直接不可用。**用户一上传就触发，无需任何罕见条件。**

**修复方向**：背景上传改传大尺寸参数（如 `compressImageFileToDataUrl(file, 2560, 0.85)`）或为背景单独保留原样读取；补一个「背景上传产物尺寸 > 1000px」的测试。

## 发现三 [P2] 常用多音字拼音首字母映射错误 — pinyin-match.js:44

`localeCompare("zh-CN")` 近似法按字的**主音**排序位置取首字母，多音字地名实测（Node ICU）全部落错：

```
✗ 重庆 → zq（应 cq）    ✗ 厦门 → sm（应 xm）
✗ 长/重 → z（作 cháng/chóng 音时应 c）
```

用户搜「cq」「xm」搜不到对应书签。多数常用词正确（淘宝 tb、京东 jd、知乎 zh、微信 wx、哔哩哔哩 blbl 均验证通过）。

**修复方向**：补常见多音字/地名白名单（重长厦行藏省数 + 重庆长沙厦门长春石家庄等），命中白名单优先于排序判定。

## 发现四 [P3] 拼音缩写仅支持连续子串 — pinyin-match.js:80

「哔哩哔哩动画」缩写为 `blbldh`，输入 `blhd`（跳字）不命中（实测 false）。子串匹配的固有限制，改为子序列匹配即可，低优先级，可选。

## 工程质量评价

高于此前几轮拆分：模块边界干净；新增的 `validateModuleTopology` 把 Firefox 模块顺序从人肉维护变成构建期强制（此前 sync-banner 曾靠人工记得登记，这个痛点被系统性解决）；`app.js` 净减约 500 行。两个 P1 都不是解耦方向的问题，而是**搬迁时对「闭包变量直写」语义的遗漏**——与 26.1.5 设置面板拆分漏注入 `SYNC_INTERVAL_OPTIONS` 属同类教训：**搬迁代码必须逐个核对所有读/写闭包变量的点，写入侧尤其容易漏**。
