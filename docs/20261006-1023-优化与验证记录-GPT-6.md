## 实现

### 测试进程隔离

原 `sync-http.test.js` 使用 `18787` 至 `18791` 固定端口，只根据健康响应判断启动完成。端口被实际服务占用时，测试可能误连该服务。

新辅助器使用系统分配端口、独立状态文件与 IPC（进程间通信）就绪消息，校验消息中的子进程 PID，再执行健康检查。启动失败、超时及进程退出都会明确报错，并保留有长度上限的诊断。停止服务后等待退出，再删除临时数据目录。

网络中断测试先持有一个动态 TCP（传输控制协议）端口并主动断连；恢复时在同一端口启动自己的同步服务。若端口被抢占，就绪握手失败，不向占用者发送测试数据。

生产服务保持原默认端口、监听地址和鉴权行为；新增显式 `PORT=0` 支持，并在私有父子进程通道报告实际监听端口。

### 界面与 Firefox 打包

- `app-i18n.js` 管理语言表、回退和按语言缓存的字典，减少渲染时重复复制整份字典。
- `ui-utils.js` 管理 HTML（超文本标记语言）转义、安全模板和异步按钮状态。
- 主应用只在初始化和事件绑定都完成后写入 `data-homepage-ready`，作为诊断与测试就绪信号。
- Node 与 PowerShell（自动化命令行）打包读取同一份 `scripts/firefox-modules.json`。PowerShell 后备路径补齐完整模块及后台脚本，防止新增模块后两种构建漂移。
- 真实浏览器测试抓到了 `escapeHtml` 漏导入问题；已修复并重新通过两端验证。说明“经典脚本能解析”不能替代模块导入和界面行为验证。

### 部署

安装脚本继续沿用现有测试令牌规则，只移除标准输出中的令牌明文。

`.github/workflows/deploy-sync-server.yml` 在主分支推送对应的 CI（持续集成）通过后触发。需配置变量 `SYNC_DEPLOY_HOST`、可选 `SYNC_DEPLOY_USER`，及 Secrets（仓库加密配置）`SYNC_DEPLOY_SSH_KEY`、`SYNC_DEPLOY_KNOWN_HOSTS`。没有目标主机变量时跳过。

工作流只更新已通过安装脚本建立的 `homepage-sync.service`，在服务器 `/opt/homepage-sync-source` 拉取并校验通过测试的提交。只替换服务代码，保留环境文件和数据；旧代码保存为 `.previous`，重启或健康检查失败则恢复旧代码。排队中的旧提交不会覆盖更新的主分支。首次安装和自定义路径服务不由此工作流接管。

本轮未设置远端主机或部署凭据，未操作实际同步服务；只验证工作流和脚本静态结构。
