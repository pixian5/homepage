## 一、补齐的同步缺口

新增 `npm run test:firefox-sync-errors`，用「真实同步服务 + 故障注入代理」的结构：

```
浏览器 → 故障注入代理(127.0.0.1:随机端口) → 真实 sync-server(127.0.0.1:随机端口)
```

代理可运行时切换 `pass / 401 / 500 / timeout / reset`，因此**不用改生产代码**就能制造异常。

| 场景 | 断言 | 结果 |
|---|---|---|
| 基线 | 正常同步成功 | ✅ |
| 错误 Token | 状态 `error` + `lastError=unauthorized` + 中文鉴权提示可见 | ✅ |
| 服务端 500 | 进入错误状态 + outbox 入队（attempts 递增） | ✅ |
| 连接重置 | 出现网络错误提示 | ✅ |
| 请求超时 | 客户端 10 秒中止（实测 11009 ms） | ✅ |
| 恢复 | 服务端可用后 outbox 自动清空、状态回 idle | ✅ |
| 同步包导出文件 | 真实 `btnSyncExportFile` 产出 2534 字节 bundle | ✅ |
| 同步包导入文件 | 真实 `btnSyncImportFile` 恢复被删书签 | ✅ |

补充的两个工程细节：

- 扩展页 CSP 的 `connect-src` 不含 `blob:`，测试里不能 `fetch(blob:)`；
  改为在 `URL.createObjectURL` 时留存 Blob 引用再读文本。
- 设置面板提交后会重建，字段可能短暂消失；测试统一用「等字段稳定再写值」。
- outbox 的退避不会因「立即同步」绕过，测试用重载页面触发首屏 `flushOutbox`。

## 二、火狐一直在下载大量内容：排查结论

用户观察到 Firefox 持续产生大量下载。逐项核实：

| 检查 | 结果 |
|---|---|
| 是否有残留测试 Firefox 进程 | 有（测试脚本结束时偶发未被清理），已全部结束 |
| `~/Downloads` 24 小时内新文件 | 仅测试产生的 `homepage-sync-2026-10-24-21-45-56.json`，已删除 |
| Firefox 更新日志 | 最后一次更新 2026-10-24 15:27，`succeeded`，之后无新增 |
| 真实 Firefox 配置 | `app.update.auto=false`；有账号登录（`signedInUser.json`） |
| 当前网络采样 | Firefox 进程 0；主要是代理客户端与编辑器 |

真正的原因有两个，都在测试脚本侧：

1. **同步 E2E 复制了真实书签**：`run-browser-sync-e2e` 会把真实 Firefox 的
   `homepage_data` 复制进临时 profile。这份数据 `iconFetch=true`、`backgroundType=bing`，
   浏览器启动后就会逐个访问几十个书签站点抓 favicon，并下载 Bing 壁纸。
2. **临时 profile 未关闭后台拉取**：Firefox 新 profile 默认仍会连账号同步、
   扩展推荐更新、遥测、Top Stories。测试跑一次就会产生可观流量。

### 已做的修复

| 脚本 | 修复 |
|---|---|
| `run-browser-sync-e2e.mjs` | 临时 profile 关闭账号同步/遥测/扩展推荐/自动更新；E2E 夹具强制 `iconFetch=false`、`backgroundType=color` |
| `run-browser-smoke.mjs` | 同上，临时 profile 关闭全部后台拉取 |
| `run-firefox-persistence.mjs` | 同上 |
| `run-firefox-sync-ui.mjs` | 同上 |
| `run-firefox-sync-flows.mjs` | 同上 |
| `run-firefox-sync-errors.mjs` | 同上；并把下载目录重定向到临时目录（`browser.download.dir`） |

修复后重新跑完全部套件，`~/Downloads` 不再新增任何文件，测试结束后也无 Firefox 残留进程。

> 如果你在**日常使用** Firefox 时仍看到大量下载，那与测试无关，需要另外排查扩展或同步服务；
> 本轮已确认测试侧不再产生流量。
