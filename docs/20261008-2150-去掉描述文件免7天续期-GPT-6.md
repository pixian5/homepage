# 去掉内嵌描述文件：7 天续期就此消失（2026-10-08 21:50）

## 触发：pass 项目为什么不用配置文件

用户指出另一个项目 `pass` 的 Safari 扩展没有配置文件也能用。取证结果：

| 检查项 | 结果 |
|--------|------|
| `/Applications/PassSafari.app/Contents/embedded.provisionprofile` | **不存在** |
| `_CodeSignature/CodeResources` 里有没有登记 profile | **没有**（说明签名时就没有，不是后来被删） |
| 签名身份 | `Apple Development: aicpc@qq.com (2P5Z4JVY8W)`，团队 `PSTNW3UN4R` |
| 签名时间 | 2026-07-31 |
| 扩展 entitlements | `app-sandbox=true`、`files.user-selected.read-only`、`get-task-allow` |
| app 内文件 | 含 `PassSafari.debug.dylib` 与 `__preview.dylib`（**Debug 构建特征**） |

pass 项目工程的签名设置也是 `CODE_SIGN_STYLE = Manual` + `PROVISIONING_PROFILE_SPECIFIER = ""`，
即 Xcode 根本不申领描述文件。

不过要注意 pass 自身的证据边界：它的 Safari 实测是通过「开发者 → 添加临时扩展」
+ 开启「允许未签名的扩展」做的，项目文档也写明
「本机缺少 `PSTNW3UN4R` 团队的开发证书和私钥，保留原安装」，
`/Applications/PassSafari.app` 是 7 月 31 日的历史产物。
也就是说：pass 提供了**线索**，但不是"安装型无 profile 扩展长期可用"的完整证明。

## 上一轮结论错了：裸二进制探针不能代表 .app

[配置文件为何必需](20261008-2135-配置文件为何必需与去掉7天续期路线-GPT-6.md) 里那六组实验
用的是 **Swift 编译出来的裸 Mach-O 命令行程序**。它得出的"必须有 profile"结论**不适用于 bundle**。

补齐实验后（同一台机器、SIP 与 Gatekeeper 均为关闭状态）：

| 组 | 形态 | entitlements | profile | 结果 |
|----|------|--------------|---------|------|
| A/E/G | **裸 Mach-O 二进制** | 沙箱（+App Group/get-task-allow 各种组合） | 无 | **exit=133 被杀** |
| I | **.app bundle** | 沙箱 + App Group | **无** | **存活，GROUP-READ-OK 36685 字节** |
| J | **.app bundle** | 沙箱 + App Group + get-task-allow | **无** | **存活，GROUP-READ-OK 36685 字节** |

I 组是关键：无 profile 的 `.app` 不仅启动成功，而且**沙箱和 App Group 都真实生效**
（读到 App Group 容器里 36685 字节的数据，没有 entitlement 时只会返回 NO-CONTAINER）。

**正确结论**：需要 profile 背书的是**裸可执行文件**；`.app` / `.appex` 这类 bundle
只要用 Apple Development 身份签名，受限权限照常生效，**不需要 Apple 另发描述文件**。
于是 7 天过期问题不存在，只剩签名证书本身的有效期（免费账号 1 年，本机到 2027-08-04）。

教训：**验证 macOS 签名行为时，探针必须做成 .app bundle，不能用裸二进制**，
否则会得出与真实目标相反的答案。

## 已实施的改动

1. `scripts/lib/safari-signing.sh` 新增 `strip_safari_provisioning_profiles <app_path>`：
   读出两端现有 entitlements → 删除宿主与扩展的 `embedded.provisionprofile`
   → 由内向外（先 .appex 再 .app）用 `--generate-entitlement-der` 重新签名 → `codesign -vv` 校验。
   entitlements 一字不改，权限不变。
2. `scripts/build-macos.command` 在 `post_sign_safari_app` 之后调用它；
   `SAFARI_STRIP_PROFILE=0` 可保留描述文件（例如要分发到别的机器时）。
3. `scripts/safari-refresh-signing.sh`：
   - 检测到已装版本无 profile 时直接退出（"nothing expires in 7 days"）；
   - 构建后同样执行 strip；strip 模式下跳过"profile 必须换 UUID"的续签校验。
4. `scripts/safari-signing-status.py`：无 profile 且签名有效时判为 `profile_free`，
   `needs_refresh=False`，输出「描述文件 : 无（已去除，不受 7 天过期约束）」。
