## 持续集成超时原因

[原失败运行](https://github.com/pixian5/homepage/actions/runs/37405342948) 的 190 项测试和三端扩展包构建均已通过，随后 Chrome（谷歌浏览器）冒烟在 45 秒后超时。

工作流使用 `browser-actions/setup-chrome@v1` 并传入 `chrome-version: stable`，实际下载普通 Chrome 154.0.8037.97 的 Linux 安装包。该浏览器忽略命令行 `--load-extension`，测试页没有加载。安装步骤的名称写成 Chrome for Testing（测试版浏览器）并不能改变下载种类。

[安装动作说明](https://github.com/browser-actions/setup-chrome/tree/v1#supported-version-formats) 区分普通发行通道和由 Chrome for Testing 提供的数字版本。修复后先读取官方 `last-known-good-versions.json` 的稳定版四段版本号，校验格式和 HTTP（超文本传输协议）状态，再将完整版本传给安装步骤。读取版本设置 15 秒超时；失败时明确停止。

冒烟脚本新增启动检查与版本日志。误传普通 Chrome 时提前报错，要求使用测试版或 Chromium（开源浏览器）；默认候选也移除普通发行版路径。

## Firefox 更新重启与清理

本机第一次验证时，Firefox（火狐浏览器）从 158.0b4 应用更新到 158.0b5，原启动进程返回 0，新进程仍持有临时测试配置。旧清理函数只观察原进程退出状态，过早删除了临时目录，留下测试实例。

已结束这次测试创建的实例并清理对应临时目录。修复包括：

- 在临时 Firefox 配置中禁用测试期间的更新，使用 `MOZ_HEADLESS=1` 和 `MOZ_NO_REMOTE=1` 固定独立、无界面模式。
- macOS 与 Linux 下为每次浏览器测试建立独立进程组。
- 清理时先请求整组退出，超时后强制结束；确认进程组消失后才删除临时配置。清理失败则保留配置并报告错误。
- 新增回归测试，模拟父进程已退出而后代仍存活，确认清理会结束后代。Windows（微软桌面系统）继续使用原有单进程清理方式，未纳入本次进程组验证。
