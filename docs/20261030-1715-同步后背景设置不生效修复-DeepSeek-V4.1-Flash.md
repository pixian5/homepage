# 同步后背景设置不生效，要手动切一次才刷新（2026-10-30 17:15）

## 现象

在别的设备上把背景改成「每日 Bing」，本机从服务器同步到数据后，
**壁纸没有变化**；必须去设置里把背景类型切到别的、再切回「每日 Bing」才会生效。

## 根因

背景只在两个时机被应用：

- 初始化：`loadBackground()`
- 设置面板里用户改「背景」下拉：`settings-controller.js` 调用 `loadBackground()`

而「数据被整包替换」的两条路径都只调了 `render()`，**没有重新应用背景**：

1. `onMerged`（同步合并成功，`src/js/app.js`）
2. `reloadFromStorage`（跨标签页 / popup 外部写入后重载，`src/js/app.js`）

`render()` 只重画卡片和分组，不碰 `#background` 元素。所以同步过来的是「设置值变了，但没人去执行」——
用户手动切一下下拉，正好触发了 `loadBackground()`，看起来就「好了」。

## 修法：用「背景签名」判断要不要重跑

不无条件重跑（每日 Bing 会重新请求网络、还会弹 toast），只在背景相关设置真的变了才刷新。

```js
function backgroundSignature(settings) {
  const s = settings || {};
  const custom = typeof s.backgroundCustom === "string" ? s.backgroundCustom : "";
  return [
    s.backgroundType || "",
    s.backgroundColor || "",
    s.backgroundGradient || "",
    custom.length,
    custom.slice(0, 32),        // 自定义图可能几百 KB，不整串比较
    Number(s.backgroundOverlayStrength) || 0,
    s.language || "",           // Bing 按语言取图
  ].join("|");
}
```

- `loadBackground()` 结束时把当前签名记到 `appliedBackgroundSignature`。
- 新增 `refreshBackgroundIfChanged()`：签名不同才 `await loadBackground()`；
  首次还没跑过（签名为空）直接返回，交给初始化流程。
- 在两处整包替换后调用：`onMerged` 里 `void refreshBackgroundIfChanged()`，
  `reloadFromStorage` 里 `await refreshBackgroundIfChanged()`。

覆盖的场景：背景类型、纯色、渐变、自定义图、遮罩强度、语言（影响 Bing 取图）——
其中任何一项由远端改动，同步完成后立即生效，不需要再手动切。

## 生效方式

- **Chrome**：未打包加载，需在 `chrome://extensions` 点刷新。
- **Firefox**：重新构建 xpi 并替换（见 20261030-1625 那篇）。
- **Safari**：跑完整的 `bash scripts/build-macos.command` 重新安装（本次仍是 `SAFARI_SKIP_APP_BUILD=1`）。

## 注意

这个修复只解决「设置值同步过来了但没执行」。如果背景图本身没同步，
那是另一回事——同步投影里只带设置和书签，**不含壁纸二进制**（自建服务端不含备份、壁纸、上传图标，
见设置面板底部说明），本机会按新的 `backgroundType` 自己去取图。
