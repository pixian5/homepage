## 一、抽离 `src/js/node-ops-manager.js`（316 行）

`createNodeOpsManager(options)` 按任务规范完整实现：

- **删除与撤销**：`deleteNodes(ids)`——级联收集（collectNodeSubtreeIds）、删除前深拷贝留存实体（撤销只恢复本次删除，避免整库快照抹掉后续编辑）、记录各容器原位置（group/folder 双形态 + index）、软删除标记 + 去重孤儿 GC + 持久化、撤销 Toast（含动作回调）、超时定时器；`undoDelete()`——先恢复实体（清软删标记与 `_syncMeta.nodeTombstones` 墓碑）再**按原 index 倒序回插**（还原出删除前的完整顺序），`getPendingDeletion()` 供测试验证挂起状态；
- **分组操作**：`deleteGroup`（固定根拦截 + confirm 注入 + 激活分组切回根 + 级联删除）、`renameGroup`（prompt 注入 + 委派 folderManager 字段时钟）、`moveGroupToIndex`（越界钳制，插入位按 visible 文件夹列表计算——与原实现逐字一致）；
- **容器导航全家桶**：getActiveGroup / getRootGroup / getRootFolderIds / getRootContainers / getRootContainerById / getFolderPlacementContainer / getPlacementList / setPlacementList / getCurrentNodes（历史分组返回注入的 recentItems）/ removeNodeFromLocation / touchPlacementContainer（nextSyncTimestamp 时钟推进）；
- prompt/confirm 可注入（测试零依赖 window 弹窗）；undoTimeoutMs 可配。

app.js 1738 → 1617 行：16 个全局函数删除、保留同名薄代理（drag-manager / grid-renderer / context-menu / history-manager / search-manager / touch-drag 等下游**零破坏性改动**）；`pendingDeletion`/`UNDO_TIMEOUT_MS` 模块变量移除；未用导入（collectNodeSubtreeIds / nextSyncTimestamp 等）与死代码清理。

2. **冒烟抓到手术误删**：python 块删除时 `getCurrentGridElement` 落在保留边界之外被误删，首页初始化抛 ReferenceError——无头 Chrome 控制台直接定位，补回 3 行函数后全绿；另清理了 biome unsafe 修复后残留的 `_undoDelete` 死代理。
