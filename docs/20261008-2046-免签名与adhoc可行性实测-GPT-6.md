# 免签名 / adhoc 签名可行性实测结论

问题：只在自己电脑上使用、不分发不上架，换电脑时用 adhoc（无证书）签名行不行？或者干脆不签名？

## 结论：都不行

- **macOS**：Safari 扩展**不能**走 adhoc，也**不能**不签名。
- **iOS**：任何情况下都必须签名，没有例外。

根因一句话：**Safari Web Extension 的 `.appex` 强制开启 App Sandbox（应用沙箱），而 adhoc 签名一旦开启沙箱就会被系统直接 SIGKILL。**

## 实测证据（本机，2026-10-08）

写了一个极简探针程序：枚举 App Group（应用组）容器 → 写文件 → 读回。
用不同签名组合重签后运行，结果如下：

| 签名方式 | entitlements（权限） | 结果 |
|----------|---------------------|------|
| adhoc（`codesign --sign -`） | 沙箱 + App Group | **SIGKILL，exit 133，无任何输出** |
| adhoc | 仅沙箱 | **SIGKILL，exit 133** |
| adhoc | 仅 App Group（无沙箱） | 成功，容器可读写 |
| adhoc | 无 entitlement | 成功，容器可读写 |
| 完全不签名 | — | 命令行能跑（本地编译产物无隔离标记） |

对照结果说明得很清楚：**被杀掉的元凶是沙箱，不是 App Group**。
只要带上 `com.apple.security.app-sandbox = true`，adhoc 签名的进程起不来。

而 App Extension 的沙箱是系统强制要求，不能关。所以 adhoc 路线在本项目上直接堵死。

补充验证：用 adhoc 重签整个 `.app`（含 `.appex`）能通过 `codesign --verify --deep --strict`，
签名信息显示 `Signature=adhoc`、`TeamIdentifier=not set`，entitlements 也都能保留——
**签名层面完全合法，问题出在运行时**。这类失败不会有任何弹窗或日志，只表现为扩展加载不出来，
极难定位，所以必须提前说清楚，不要靠"试一试看起来能装上"来判断。

## 平台的硬约束

### macOS

- 现代 macOS（尤其 Apple Silicon）要求可执行代码必须带签名，至少是 adhoc 级别。
- Safari 只加载签名有效的 `.appex`，未签名的一律不加载。
- `.appex` 强制 App Sandbox → 必须有 Team ID（团队标识）→ 必须有 Apple Development 证书 + Provisioning Profile。
- 因此：**换电脑后必须重签，且必须用真实开发身份**。这也是 `scripts/build-macos.command` 存在的原因。

### iOS

- **完全不存在免签名运行**。iOS 上每个可执行文件都必须签名。
- "Ad Hoc" 这个词在 iOS 语境里是误导：它指 **Ad Hoc Distribution（临时分发）**——
  付费账号 + 登记设备 UDID + 最多 100 台设备，**仍然要签名**，不是免签名。
- 免费 Apple ID 真机调试：签名 **7 天**有效，最多 3 个 App ID，到期必须重新连 Xcode（集成开发环境）续签。
- 付费账号（Individual / Organization）：开发证书与描述文件最长 **1 年**。

## 真正的痛点与降本方案

既然签名绕不开，真正的麻烦不是「换机」，而是 **描述文件 7 天就过期**。

当前本机实测的两份 profile：

```
Name            = Mac Team Provisioning Profile: com.aeroluna.homepage.safari
IsXcodeManaged  = true
LocalProvision  = true
TimeToLive      = 7                    # 创建 2026-10-08，到期 2026-10-15
TeamName        = 姬 楠彩
TeamIdentifier  = WY97WQFBKC
```

`IsXcodeManaged = true` + `TimeToLive = 7` 是 Xcode 自动管理的典型特征。
免费 Apple ID（Personal Team）是 7 天；付费会员的自动管理 profile 通常是 365 天。
所以当前账号**很可能是免费 Apple ID**，需要先确认。

自查方法：登录 `developer.apple.com/account` 看 Membership（会员）状态。
如果能进入并创建 Certificates, Identifiers & Profiles 里的 **macOS App Development** profile，就是付费会员。

### 方案 A：免费账号，接受 7 天，做一键续签（推荐先做）

改造成"只刷新签名"的快速路径：`SAFARI_REFRESH_SIGNING=1` 时跳过 converter（转换器）、
跳过资源同步与全量重编译，直接重跑 `xcodebuild` 的签名阶段 + 后签名 + 安装校验。
把每周一次的重跑从"几分钟全量构建"压到"十几秒续期"。

### 方案 B：付费会员，手工建 1 年 profile（一劳永逸）

1. 开发者后台新建 **macOS App Development** profile，App ID 选 `com.aeroluna.homepage.safari`，
   勾选 App Groups 能力，设备勾选这台 Mac。
2. 下载放到 `~/Library/MobileDevice/Provisioning Profiles/`。
3. 工程改 **Manual signing（手动签名）**，显式指定该 profile 与 Apple Development 证书。
4. 有效期跟随证书，最长 1 年，一年才需要动一次。

### 方案 C：去掉 App Group 能不能免签名

不能。即便移除 App Group，`.appex` 的强制沙箱仍在，adhoc 照样被杀。此路不通。

## 附带结论：数据兜底是有效的

`~/Library/Group Containers/group.com.aeroluna.homepage.safari/homepage-data.json` 存在，
说明 App Group 兜底副本在正常写入。即便换机导致 Safari 扩展身份变化，数据也有恢复来源。
