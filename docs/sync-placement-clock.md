# 书签位置同步时钟

## 问题

旧实现用父容器的 `updatedAt` 作为其中所有书签的位置版本。设备在根目录新增一个无关书签时，根目录内每个旧位置都会被错误标记为最新，可能覆盖另一设备已经完成的移动。

## 数据模型

每个可见节点在 `_syncMeta.placementClock[nodeId]` 中保存独立位置版本：

```json
{
  "parentKind": "folder",
  "parentId": "fld_work",
  "index": 2,
  "updatedAt": 1786000000000,
  "updatedBy": "dev_xxx"
}
```

`parentKind + parentId` 决定唯一父位置，`index` 决定父容器内顺序，`updatedAt + updatedBy` 用于跨设备确定性裁决。

## 写入规则

- 首页加载或同步合并后记录位置快照。
- 保存前比较当前位置与快照，仅为父位置或顺序发生变化的节点更新时间。
- 扩展图标弹窗新增书签绕过首页保存流程，因此在后台写入时直接创建位置时钟。
- 同步合并保存每个节点胜出的位置时钟，下一轮投影继续使用，不退回父容器时钟。
- 位置时钟只保留当前可见节点；节点删除后立即清理对应记录，避免长期累积。
- 旧数据没有独立时钟时仍以父容器时间作为兼容回退；节点首次移动或排序后自动进入新模型。

## 冲突规则

同一节点只能保留一个父位置。比较顺序为：

1. `updatedAt` 较新者胜出。
2. 时间相同时，删除位置优先。
3. 再以 `updatedBy`、父位置和索引确定性裁决。

父容器中的无关新增、删除或编辑不会再提高其他节点的位置版本。

## 导入与深层目录

- “仅新增不覆盖”继续只追加不存在的 ID，本机同 ID 节点不变。
- “合并现有”通过同步合并器按节点字段时钟和位置时钟合并同 ID 数据。
- 导入去重使用显式栈深度遍历，可处理至少 10,000 层文件夹而不触发 JavaScript 调用栈溢出。
