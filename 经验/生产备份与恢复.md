# 生产备份与恢复经验

## 备份

```bash
sudo scripts/backup-sync-state.sh
```

备份前校验状态 JSON，归档只包含状态目录内容，并保留固定数量的最近备份。生产操作应记录
revision、epoch、docId、contentHash、设备数量和墓碑数量。

## 恢复

先 dry-run：

```bash
sudo scripts/restore-sync-state.sh \
  --archive /var/backups/homepage-sync/homepage-sync-YYYYMMDDTHHMMSSZ.tar.gz \
  --dry-run
```

确认归档后再正式恢复。脚本会临时解包，校验 JSON、schema、revision、`doc.revision` 和
`contentHash`，然后用同级目录 rename 切换；启动失败或 `/health` 失败会自动回滚。

本机隔离演练：

```bash
bash scripts/run-sync-recovery-drill.sh
```

## 回收

1. 先备份。
2. 调用 `POST /v1/sync/reclaim` dry-run，保存候选设备、revision 和 epoch。
3. 人工确认候选设备确实退役。
4. 使用 `{"dryRun":false,"confirm":"RECLAIM","maxCandidates":N}` 执行受限回收。
5. 用各浏览器验证 stale epoch、重新拉取和后续 push。

不要把真实回收加入无人值守定时任务；候选设备错误会造成离线数据丢失风险。
