版本：26.0.0。运行器：Mozilla Firefox 159.0b5（Developer Edition，本机已安装）。
环境：macOS 27.0.1。

## 为什么单独做这套验证

用户正在使用 Chrome，不能抢占它的配置；同时不能下载新浏览器（流量受限）。
因此本轮只动 Firefox，并满足：

- 使用**临时 profile** 与**临时扩展副本**，不触碰真实 Firefox 配置（`~/Library/Application Support/Firefox/Profiles/...`）；
- 全程 `--headless`，不弹窗口、不影响前台使用；
- 不联网，测试数据全部是本地合成数据；
- 复用本机已缓存的 Chrome for Testing 做 Chrome 侧的补充冒烟，**没有下载任何东西**。

## 这次踩到的测试坑（已修在脚本里）

1. **入口脚本被替换**：临时扩展把 `newtab.html` 的 `app.ff.js` 换成了测试运行器，
   运行器必须自己再动态加载 `js/app.ff.js`，否则页面永远不 ready。
2. **事件类型要匹配**：设置项里数字/文本输入框监听的是 `input`，复选框与下拉框监听 `change`；
   测试同时派发两者，才与真实用户操作一致。
3. **无头模式读不到剪切板**：Firefox 以“缺少用户激活”拦截 `navigator.clipboard.readText()`。
   改为包一层 `writeText` 捕获真实导出处理函数写入的内容，导出的仍是原逻辑产物。
4. **卸载模拟要清干净**：临时扩展每次安装 UUID 可能不同，会留下多个
   `storage/default/moz-extension+++*` 目录；必须全部删除并清掉 `storage-sync-v2.sqlite`，
   否则本地残留数据让“重装后恢复”的测试变成假通过。
5. **断言要区分字段**：导出 JSON 里没有字面量 `homepage`，用 `nodes` 字段判定更可靠。

## 结论

Firefox 侧的数据持久化、备份恢复、导出/导入、以及“卸载重装后用导出文件恢复”全部通过，
与 Safari 26.0.0 的结论一致。Chrome 侧冒烟也通过，但**未**在真实 Chrome profile 上做重装恢复，
避免影响用户正在使用中的浏览器；需要时可用 Chrome for Testing 单独跑一轮。
