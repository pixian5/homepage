# 图标与背景缓存瘦身（2026-10-28 11:45）

版本：26.3.5 → **26.3.7**。对应[复核与下一步开发方案](20261028-0832-复核与下一步开发方案-GLM-5.3.md)第 5 步。

**要解决的问题**：本地存储被缓存吃掉 87%，主数据只有 179KB，而缓存合计 1.2MB。缓存长期只增不减。

---

## 一、实测数据（优化前，本机 Safari）

| 存储键 | 字节 | 占比 |
|---|---|---|
| `homepage_icon_cache` | 774,682 | 55% |
| `homepage_bg_cache` | 442,479 | 31% |
| `homepage_data` | 179,210 | 13% |
| 其它（访问历史等） | ~16,000 | 1% |
| **合计** | **~1,405,000** | |

## 二、定位到的三个问题

### 问题 1：背景缓存纯浪费（442KB）

`homepage_bg_cache` 存着**一整张 Bing 壁纸的 dataURL**（442,317 字节）。而 `loadBackground()` 只有 `backgroundType === "bing"` 时才会调用 `getBingWallpaper()`；26.0.4 起默认背景已是纯色，这张图**永远不会被再次读取**，却一直占着 31% 的存储。

### 问题 2：图标缓存没有孤儿清理

缓存 key 有 URL 维度和 `site:` 维度两套。删除书签后，对应缓存条目**永远留着**。实测 82 条缓存里 82 条都能对应到现有书签，但这是巧合——代码里从未有过按书签集合反向清理的逻辑。

### 问题 3（最大）：单条图标体积无上限

`ICON_DATA_MAX_LENGTH = 2048` 这个常量**只用于同步投影裁剪**（`sanitizeForSync`），从不限制本地缓存。

实测：单条均值 **9,890 字节**，最大 **42,796 字节**（chatgpt.com 的图标存了三份：URL 版、`site:` 版、还有 `/codex` 页面版）。78 条里有 **49 条超过 2048 字节**。抓取到的原始 favicon 常是几百 KB 的 PNG，被原样存进了 `storage.local`。

---

## 三、实现

### 3.1 孤儿清理 `pruneIconCacheOrphans()`（storage.js）

按当前书签集合反向过滤：

- URL 维度：书签里存在同 URL 才保留；
- `site:` 维度：书签里存在同站点才保留（同站点的其它页面仍可能复用）。

**关键细节**：站点键生成必须复用 `icons.js` 的 `getSiteKey()` —— 我自己另写一版（归一去 `www.`、排除 localhost）会与真实键规则不一致，导致误删。改为通过 `siteKeyOf` 参数注入原函数。

### 3.2 单条体积上限（storage.js）

`ICON_CACHE_ENTRY_MAX_CHARS = 16 * 1024`，在 `evictIconCacheLRU()` 里先按体积过滤、再按数量淘汰。超限条目丢弃，渲染时回退字母头像——视觉损失很小，体积收益很大。

顺带修了一个真实 bug：`normalizeIconCacheEntry` 原来用 `entry.ts || now`，**合法的 ts 为 0 时会被当成缺失刷成 now**，使极旧条目变成最新、破坏 LRU 顺序。改为 `Number.isFinite(entry.ts) && entry.ts > 0`。

### 3.3 背景缓存清理 `pruneUnusedCaches()`（storage.js）

背景类型不是 `bing` 时，把壁纸 dataURL 清空（保留结构，避免读取方拿到 null 出错）。

### 3.4 启动时静默执行（app.js）

首屏渲染后异步调用，不阻塞加载；失败只打日志。同时把 `consumeSaveToast()` 的 `await` 改为 `void`（它是 UI 提示，不该拖慢启动）。

## 四、实测结果（本机 Safari，26.3.7）

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 图标缓存 | 774,682 | **287,180** | **−487KB** |
| 背景缓存 | 442,479 | **40** | **−442KB** |
| 总占用 | ~1,405,000 | **474,848** | **−930KB（−66%）** |

**功能验证**：33 个卡片正常渲染、无致命错误；**33 个图标全部仍是 dataURL 图片，0 个回退字母头像**——说明清掉的全是超限巨图与孤儿，真实书签图标一个没丢。

单元测试 **226/226** 通过（新增 8 条），Biome 80 文件零警告。

## 五、后续可考虑

- 抓取时就压缩图标（canvas 缩放到 32×32 再转 dataURL），而不是事后丢弃；这样大图标也能保留缩略版；
- `visit-history` 目前 8KB，量级很小，暂不处理。
