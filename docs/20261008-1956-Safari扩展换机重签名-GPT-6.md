# Safari 扩展换电脑重新签名与安装

记录把「我的首页 Safari」从旧电脑迁到新电脑时，重新签名并让 Safari 重新识别扩展的完整流程。

## 结论先行

**不要手工 `codesign --force --sign` 了事。** 换电脑时真正失效的不是证书，而是内嵌的 **Provisioning Profile（描述文件）**。
只换签名不换描述文件，扩展在 Safari 里会出现「装了但加载失败 / 勾不上 / 立即变灰」，而且报错信息毫无指向性，排查成本极高。

正确做法：**重新走一遍构建流程**，让 Xcode 用当前钥匙串身份重新申请描述文件并重新签名。
一键入口是 `scripts/build-macos.command`。

## 本次实测环境（新电脑）

| 项目 | 实测值 |
|------|--------|
| 系统 | macOS（Safari 27.0.1） |
| Xcode | 27.0（27A266a） |
| 钥匙串身份 | `Apple Development: ibjxk0@gmail.com (YGR8677YMA)` |
| Team ID（团队标识） | `WY97WQFBKC` |
| 证书链 | Apple Development → WWDR Certification Authority → Apple Root CA（完整可验） |
| 本机平台 UUID | `6335600C-6389-5916-BD28-713A5065CEAB` |
| `~/Library/MobileDevice/Provisioning Profiles/` | **不存在（目录都没有）** |
| `/Applications/我的首页 Safari.app` | 存在，签名有效，但**内嵌描述文件已过期** |

关键诊断命令与结果：

```bash
# 旧 .app 里内嵌描述文件的有效期
security cms -D -i "/Applications/我的首页 Safari.app/Contents/embedded.provisionprofile" \
  | plutil -extract ExpirationDate raw -o - -
# => 2026-08-19T13:31:52Z   （今天 2026-10-08，已过期近两个月）

# 该描述文件登记的设备数量
security cms -D -i ".../embedded.provisionprofile" \
  | plutil -extract ProvisionedDevices xml1 -o - - | grep -c "<string>"
# => 1   （只有旧电脑，不含本机）

# Safari 扩展注册表
plutil -p ~/Library/Safari/Extensions/Extensions.plist   # => 空
pluginkit -m -p com.apple.Safari.web-extension | grep homepage
# => 只列出 com.aeroluna.homepage.safari.extension(25.6)，未真正启用
```

也就是说：**签名没问题，团队也没变，但描述文件又过期又不覆盖本机**，这才是拷贝过来的 `.app` 装不上的根因。

## 为什么换电脑会坏

1. 本项目宿主 App 用了 **App Group（应用组）** `group.com.aeroluna.homepage.safari` 做数据兜底。
   App Group 属于受限能力，**必须由描述文件授权**，光有证书不算。`codesign` 加的 entitlement 若不在描述文件白名单里，运行时直接失效。
2. Apple Development 描述文件有**有效期（本次实测约一年）**，并且登记**允许运行的设备**。
   旧电脑签出来的内嵌描述文件不会自动覆盖新电脑。
3. 描述文件参与 bundle 内容签名摘要。**只替换 `.provisionprofile` 不重签 = 签名校验失败**；
   **只重签不换描述文件 = 授权依旧无效**。两者必须一起做。
4. Safari 判断扩展身份靠 **Bundle ID + Team ID**。团队不变（`WY97WQFBKC`）就是同一个身份，App Group 里的 `homepage-data.json` 仍可读；
   如果哪天换成别的团队，Safari 会当成全新扩展，历史数据要靠 App Group 兜底恢复。

## 推荐流程：重跑构建脚本（正规路径）

### 第 0 步：Xcode 登录同一个 Apple ID（唯一必须手工做的）

`Xcode（集成开发环境） → Settings（设置） → Accounts（账户）` 添加 `ibjxk0@gmail.com`。
构建脚本用 `-allowProvisioningUpdates`，靠这个登录态自动注册本机、自动拉取含 App Group 的新描述文件。没登录这一步，后面全白搭。

验证：

```bash
# 能看到 Apple Development 身份即钥匙串 OK
security find-identity -p codesigning -v | grep "Apple Development"

# 顺便确认中间证书在（缺了会报 CSSMERR_TP_NOT_TRUSTED）
security find-certificate -c "Worldwide Developer Relations" -a | grep alis
```

### 第 1 步：执行构建

```bash
cd /Users/x/code/homepage
bash scripts/build-macos.command
```

脚本（`scripts/build-macos.command` + `scripts/build.sh`）内部依次完成：

1. 先让 Safari 退出（运行时写回会污染扩展状态），再做存储快照 `scripts/safari-storage-guard.py snapshot`；
2. `xcrun safari-web-extension-converter` 生成/复用 Xcode 工程到 `dist/safari-app`；
3. `detect_apple_development_team` 探测 Team ID，并把它写进 `project.pbxproj` 的 `DEVELOPMENT_TEAM`、
   把 `CODE_SIGN_IDENTITY` 统一成 `Apple Development`——**新电脑自动带上 `WY97WQFBKC`，不用手填**；
4. `xcodebuild -allowProvisioningUpdates` 构建 Release，自动更新描述文件；
5. `post_sign_safari_app` 用 Apple Development 身份重签（**先 `.appex` 后 `.app`**，顺序不能反），
   并 `codesign --verify`；
6. `verify_stable_storage_entitlements` 校验宿主 App 和扩展**双方**都带 App Group，缺一直接构建失败；
7. 拷贝到 `/Applications/我的首页 Safari.app`；
8. `scripts/clean-safari-homepage-registrations.mjs` 清理历史身份造成的重复条目
   （只清 `PSTNW3UN4R` 和 `UNSIGNED`，保留 `WY97WQFBKC`）；
9. `safari-storage-guard.py verify --restore-on-regression` 比对数据哈希，发现被默认值覆盖就自动回滚并让构建失败；
10. `safari-newtab-selection.py configure` 把「新建标签页/窗口时打开」重新指向当前签名身份，并立即校验；
11. `lsregister -u` 注销构建产物路径，避免 Safari 扩展列表出现两个同名条目。

### 第 2 步：在 Safari 里启用

`Safari → 设置 → 扩展`，勾选「我的首页」。
**新电脑第一次不会自动启用**，这一步不做，前面全白做。

如果是从旧电脑拷贝的 `.app` 而非构建产物，首次打开会被 Gatekeeper（门禁）拦：
**右键 → 打开**；或用命令行清隔离标记：

```bash
xattr -dr com.apple.quarantine "/Applications/我的首页 Safari.app"
```

## 应急路径：只重签已有 .app（不改代码时）

准备：从 Xcode 或开发者后台拿到**含 App Group 且未过期**的 macOS Development 描述文件 `embedded.provisionprofile`。

```bash
APP="/Applications/我的首页 Safari.app"
APPEX="$APP/Contents/PlugIns/我的首页 Safari Extension.appex"
IDENTITY="Apple Development: ibjxk0@gmail.com (YGR8677YMA)"

# 1) 替换内外两处描述文件（宿主 App 和扩展各一份）
cp embedded.provisionprofile "$APP/Contents/embedded.provisionprofile"
cp embedded.provisionprofile "$APPEX/Contents/embedded.provisionprofile"

# 2) 从内到外重签，entitlements 必须显式带上，否则 App Group 被抹掉
codesign --force --sign "$IDENTITY" --entitlements appex.xcent --timestamp=none --options runtime "$APPEX"
codesign --force --sign "$IDENTITY" --entitlements app.xcent  --timestamp=none --options runtime "$APP"

# 3) 深度校验
codesign --verify --deep --strict --verbose=2 "$APP"

# 4) 确认 App Group 还在
codesign -d --entitlements :- "$APP"   | grep group.com.aeroluna.homepage.safari
codesign -d --entitlements :- "$APPEX" | grep group.com.aeroluna.homepage.safari
```

`.xcent` 从构建产物取，路径见 `scripts/build-macos.command` 的 `post_sign_safari_app()`：
`dist/safari-app/build/Build/Intermediates.noindex/我的首页 Safari.build/Release/...`
**没有 `.xcent` 就别手签**——漏掉 entitlement 导致的扩展加载失败极难定位。

## 陷阱清单

- 导出的是证书（`.p12`）不是描述文件 → 不够用。两者都要，且描述文件必须是本机的。
- 手动 `codesign --force --sign` 却沿用旧描述文件 → 授权依旧过期，白签。
- 先签外层 `.app` 再签内层 `.appex` → 外层签名被内层改动破坏，顺序必须**由内向外**。
- 只给宿主 App 加 App Group、忘了扩展 → Safari 扩展读不到共享数据，`verify_stable_storage_entitlements` 会拦下。
- 忘记 Safari 里手动启用 → 装完仍然没生效。
- Safari 没退干净就装 → 内存里的旧状态写回，扩展列表出现幽灵条目。
- 换了团队签名 → Team ID 变化，Safari 视作新扩展，需靠 App Group 副本恢复数据。
- 本地开发分发**不需要** Developer ID，也**不需要公证**；`Apple Development` + 有效描述文件即可，公证是 Developer ID 分发才要的环节。

## 两个额外注意点

1. **不用关 Gatekeeper（门禁）**。本地 Xcode 构建产物不带 `com.apple.quarantine`，`spctl` 评估根本不会拦。
   为此执行 `sudo spctl --master-disable` 是多余的，而且它会**全局关闭应用评估、削弱系统安全**。
   已经关掉的，建议开回来：

   ```bash
   sudo spctl --master-enable   # 随后需到 系统设置 → 隐私与安全性 确认
   ```

2. **Xcode 自动签发的开发 profile 只有 7 天有效期**（本次实测 2026-10-15 到期）。
   到期后扩展会失效、表现和这次换机时一样。解决办法就是**重跑一次构建脚本**，
   `-allowProvisioningUpdates` 会自动续期并重新签名。可以把「一周后重跑构建」当作常规维护动作。
