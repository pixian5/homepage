# 同步设置面板补「上次同步时间」（2026-10-30 17:05）

## 起因

用户在 Chrome 里点了横幅的「关闭」，然后打开设置面板查看，界面上只有这一行：

```
已启用 · 服务器同步 (HTTP) · 同步间隔: 仅手动/变更时 · 同步数据约 24.3 KB · 体积正常
```

**没有任何「上次同步是什么时候」的信息**，于是无法判断同步到底成功没有。
实际核查存储，那一刻同步其实已经成功过（`lastPushAt` 有值、`status=idle`、revision 50），
但界面没给证据，用户只能靠猜——这是面板的信息缺口，不是同步故障。

## 改动

### 1. 状态行增加「上次同步」

`src/js/settings-controller.js` 的 `refreshSyncStatusLine()`：

```js
const lastAt = Math.max(Number(st.lastPullAt) || 0, Number(st.lastPushAt) || 0);
const lastLabel = ` · ${lastAt > 0
  ? t("settings.sync.lastSync", { time: formatSyncTime(lastAt) })
  : t("settings.sync.lastSync.none")}`;
```

取 pull / push 里较晚的一次。新增 `formatSyncTime()`：

- 当天 → `HH:MM`
- 跨天 → `MM-DD HH:MM`（不加年份，面板本来就长）

改后的状态行长这样：

```
已启用 · 服务器同步 (HTTP) · 同步间隔: 仅手动/变更时 · 上次同步 16:52 · 同步数据约 24.3 KB · 体积正常
```

### 2. 三个语言包补两条文案

`src/js/app-i18n.js`：

| key | zh-CN | zh-TW | en |
|---|---|---|---|
| `settings.sync.lastSync` | 上次同步 {time} | 上次同步 {time} | Last sync {time} |
| `settings.sync.lastSync.none` | 尚未同步过 | 尚未同步過 | Never synced |

## 为什么不用「同步成功」的 toast

toast 是瞬时的，划过去就没了；用户真正需要的是**随时可查的持久证据**。
面板里常驻一行时间，比弹一次提示更能解决「到底同步没有」这个问题。

## 验证

- `node --test`：250 项全过
- `npm run check`（biome）：83 个文件无告警
- `SAFARI_SKIP_APP_BUILD=1 bash scripts/build.sh` 构建通过，`dist/chrome/js` 里确认包含
  `settings.sync.lastSync`（6 处，三语各两条）与 `formatSyncTime`（2 处）

## 生效方式

- **Chrome**：扩展是未打包加载（读 `dist/chrome`），需到 `chrome://extensions` 点一次刷新。
- **Firefox**：需重新构建 xpi 并替换（同 20261030-1625 那篇的流程）。
- **Safari**：需跑完整的 `bash scripts/build-macos.command` 重新打包安装（本次为省时间用了
  `SAFARI_SKIP_APP_BUILD=1`，只更新了工程资源，没有重建 App）。
