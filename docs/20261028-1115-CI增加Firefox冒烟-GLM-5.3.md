# CI 增加 Firefox 冒烟（2026-10-28 11:15）

版本：26.3.1 → **26.3.2**。对应[复核与下一步开发方案](20261028-0832-复核与下一步开发方案-GLM-5.3.md)第 4 步。

**要解决的问题**：CI 原来只跑 Chrome 冒烟。历史上 Firefox 专属的 bug（事件类型差异、会话恢复、后台大量下载）全是手工发现的，一旦回归就是线上问题。

---

## 一、改动

`.github/workflows/ci.yml` 在 Chrome 冒烟之后新增两步：

```yaml
- name: Setup Firefox Developer Edition
  id: firefox
  uses: browser-actions/setup-firefox@v1
  with:
    firefox-version: latest-devedition

- name: Run Firefox smoke tests
  env:
    FIREFOX_E2E_BINARY: ${{ steps.firefox.outputs.firefox-path }}
  run: |
    if ! command -v zip >/dev/null 2>&1; then
      sudo apt-get update -qq
      sudo apt-get install -y -qq zip
    fi
    "$FIREFOX_E2E_BINARY" --version
    npm run test:browser-smoke -- firefox
```

### 为什么必须是 Developer Edition（重要）

冒烟脚本加载扩展的方式是：`xpinstall.signatures.required=false` + 把未签名 XPI 放进临时 profile。**release 版 Firefox 会忽略这个偏好**，扩展根本装不上，冒烟必然失败。所以 `latest-devedition`（或 nightly/beta）是硬要求，不是偏好。

同理 Chrome 那边也必须用 Chrome for Testing —— 普通发行版会忽略 `--load-extension`。

### 为什么额外装 zip

脚本用 `zip` 把扩展目录打成 XPI。ubuntu-latest runner 通常自带，但不保证；缺失时 Firefox 用例会以「扩展压缩失败」报错，看着像扩展问题、实际是环境缺工具。显式检查一次，错误信息更清楚。

## 三、新增配置守卫测试

`tests/ci-workflow.test.js`（4 条，已做变异验证）：

| 断言 | 防的是什么 |
|---|---|
| CI 同时跑 chrome 与 firefox 冒烟 | 有人删掉 Firefox 步骤 |
| `firefox-version` 必须是 devedition/nightly/beta | 改回 `latest` 会让扩展装不上、CI 红但原因难查 |
| 必须传 `FIREFOX_E2E_BINARY` | 路径没传进去，脚本回退到不存在的默认路径 |
| 运行前确认 zip 可用 | runner 缺 zip 时报错信息会误导成扩展问题 |

**变异验证**：把 `latest-devedition` 改成 `latest` 后跑测试 → 立即失败并输出 `firefox-version=latest 无法加载未签名扩展，请改用 latest-devedition 等版本`；改回后 4/4 通过。
