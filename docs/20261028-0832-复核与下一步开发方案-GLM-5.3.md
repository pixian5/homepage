## 二、下一步开发方案（按轮次）

### 轮次 1：修 412 重试两缺陷 + 回归测试（约半天，最优先）

改动都在 `src/js/sync_engine.js` 的 `pushNowImpl`：

1. **P1**：412 分支内补 `if (writeErr.etag) _status.lastRemoteEtag = writeErr.etag;`（与 `resolveDocConflict` :662 的正确写法对齐）；
2. **P2**：`const latest = _getData();` 从循环外移入循环内每次重取（与 :509 outbox 兜底的现取写法对齐）；
3. **顺手 P3-1～P3-4**：幂等键改为稳定键（`docId:revision:deviceId`，去掉 `Date.now()`）；删 :303 死三元；`saveState` 增加持久化 `lastRemoteEpoch`；服务端 CORS 的 `Allow-Headers`/`Expose-Headers` 补 `X-Sync-Epoch`；
4. **新增回归测试**：本地起 `sync-server.mjs` + 注入代理在首个 PUT 前写入并发版本；断言 ① PUT #2 起携带新 etag；② `pushNow` 最终 `ok:true`；③ 服务端文档同时含本机与并发方的变更（覆盖 P2）。

**验收**：`npm test` 全绿（204+ 条）、`npm run check`、Firefox 冒烟、双标签页同步手测。
**风险**：低——主改动约三行；注意 `latest` 移入循环后，循环末尾 outbox 兜底仍保持现取。

### 轮次 2：服务端备份/恢复脚本（0.5 天）

- `scripts/backup-sync-state.sh`：服务器端 tar `/var/lib/homepage-sync`、保留最近 N 份、支持拉回本机；
- `scripts/restore-sync-state.sh`：停服务 → 校验 JSON → 替换 → 启动 → `/health` 验证；
- 部署 `oh.sbbz.tech` 与日后回收演练、服务端升级前都必须先跑备份。

### 轮次 3：同步可见性（1 天）

- **失败提示条**：`_status.status === "error"` 持续超阈值（如 24 小时）或 outbox `attempts` 达上限时，新标签页顶部显示可关闭横幅（记录 dismissedAt，24 小时内不再弹），按钮「立即重试」（调 `pushNow()`）与「查看设置」；
- **跨标签页状态**：[app.js:423](../src/js/app.js) 的 `storage.onChanged` 增加 `SYNC_STATE_KEY` 监听，变化时刷新状态栏与冲突按钮；
- 测试：storage 事件模拟 + outbox 耗尽场景单测。

### 轮次 4：CI 加 Firefox 冒烟（0.5 天）

CI 安装 Firefox（`browser-actions/setup-firefox` 或系统包），跑 `npm run test:browser-smoke -- firefox`；Safari 保持本机专项。

### 轮次 5：图标/背景缓存瘦身（1 天）

删书签时同步删图标缓存；启动按当前书签 URL 集合清孤儿；背景缓存只留当天与前一天。

### 轮次 6：拆拖拽控制器（2～3 天，可分次）

先补拖拽/放置纯函数测试再搬代码；同步更新 `scripts/firefox-modules.json`；每步跑全量测试 + 双浏览器冒烟。

### 轮次 7：设备退役 + 独立凭据 + 首次生产回收演练（2～3 天 + 全设备协调）

服务端退役端点、设备级凭据；首次生产回收流程：全设备确认 → `reclaim` dryRun 核对 → 备份 → 真回收 → 各端确认新 epoch。

### 配合项（部署动作，轮次 2 完成后随时可做）

在 `oh.sbbz.tech` 用 `setup-sync-server.sh` 部署最新服务端 → 各端改服务器地址 → 手动「立即同步」→ `/health` 与 `/v1/sync/devices` 验证。
