## 一、实现内容

### 1.1 服务端删除版本（`deletions`）

- 状态文件新增 `deletions: { id: revision }`。
- **删除版本由服务端写入，客户端不能伪造**：PUT 时若节点/分组带 `deletedAt`/`purgedAt`
  且索引中还没有该 ID，就记为本次提交的 revision。
- 随文档、设备表一起**原子落盘**，避免只写一半。

### 1.2 回收候选判定

```
候选 = { id | deletions[id] <= min(所有有效设备 lastConfirmedRevision) }
有效设备 = lastConfirmedEpoch >= 当前 epoch
```

- 长期离线设备不会被时间自动回收，只有**确实确认过删除**的设备才参与判定。
- 旧代际的确认不算数（回收后所有设备确认进度会重置）。

### 1.3 回收端点 `POST /v1/sync/reclaim`

| 参数 | 行为 |
|---|---|
| 缺省 / `{"dryRun": true}` | 只返回候选列表，**不改任何数据** |
| `{"dryRun": false}` | 删除候选墓碑，**revision +1、epoch +1**，重置所有设备确认进度 |

- 回收时同时清理 placements 中指向被删节点的条目。
- 响应头返回 `X-Sync-Epoch`。

### 1.4 压缩代际栅栏

- PUT 支持 `X-Sync-Epoch` 头；若客户端代际**落后**于服务端，返回 `409 stale_epoch`。
- 未声明代际的旧客户端仍放行（第一阶段兼容），但新客户端会带代际。
- 客户端（`sync_engine.js`）：
  - 拉取时记录服务端 epoch；
  - 推送时带上该 epoch；
  - 收到 `stale_epoch` 时**不进入 outbox**，而是立刻重新拉取基线。

### 1.5 诊断视图

`GET /v1/sync/devices` 现在返回：

```json
{
  "revision": 12,
  "epoch": 1,
  "devices": [...],
  "deletions": { "n1": 11 },
  "reclaimCandidates": ["n1"]
}
```

## 四、尚未启用的部分（重要）

**回收端点当前不会自动运行**。需要人工调用：

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"dryRun": true}' \
  https://<server>/v1/sync/reclaim
```

建议流程：
1. 先 `dryRun: true` 看候选，确认没有误判；
2. **备份服务端状态文件与各客户端数据**；
3. 再执行 `dryRun: false`；
4. 所有客户端下次同步时会自动取新基线。
