# 27.2.0：持久化基线失败回滚与备份删除/清空/并发编辑保存出口全闭环

## 问题与实现

1. **持久化协调器（`src/js/persistence-coordinator.js`）内部基线原子回滚**：
   - `persistData()` 原先在调用 `saveData(data, false)` 之前就已经执行了 `ensureAutoBackupBeforePersist()`、`stampSettingsClockBeforePersist()` 与 `stampPlacementClockBeforePersist()`，导致写盘失败或抛异常时，自动压入的备份快照、备份指纹以及设置/放置双时钟基线已被提前推进，下次重试保存时会漏打时钟或漏生成自动备份。
   - 现改为在 `run()` 入口处记录备份指纹、基线快照、`skipAutoBackupOnce`、`data.backups` 以及双时钟基线快照；只要 `saveData()` 返回非告警错误或抛出异常，立即原子回滚上述全部内部基线与自动备份。

2. **备份删除、备份恢复与清空数据/卡片写盘失败回滚（`src/js/import-export.js`、`src/js/settings-controller.js`）**：
   - 备份删除（`.backup-delete`）原先使用 `queuePersist()` 吞掉失败并直接刷新弹窗、提示「已删除备份」。现统一接入 `commitImport()`，等待 `persistData()` 返回 `ok: true` 后才重绘弹窗与提示成功；写盘失败时回滚原备份列表并报错，支持原地重试。
   - 备份恢复（`.backup-restore`）统一走 `commitImport()`，补齐失败时对 `resetSettingsClockBaseline` 与 `resetPlacementClockBaseline` 的回滚。
   - 设置面板的「清空数据」（`btnClearData`）与「清空所有卡片」（`btnClearCards`）补齐 `persistData()` 返回值校验与异常捕获，写盘失败时恢复原数据、原活跃分组及三项基线，不关闭弹窗、不误报成功。

3. **导入写盘期间的并发编辑与跨标签页重载保护（`src/js/import-export.js`）**：
   - `openImportModal` 在进入 `commitImport` 前先行解析 `deviceId`，消除 `change()` 内的异步等待窗口。
   - 在 `commitImport()` 中记录 `change()` 完成后的候选快照 `postChangeSnapshot`：若 `persistData()` 等待期间其它标签页重载替换了 `data`（`getData() !== workingData`），失败回滚时保留最新外部数据而不被旧快照覆盖；若当前页在等待期间发生了原地并发编辑（新增/修改/删除节点、分组或设置），回滚失败导入的同时将并发增量合并回原对象。
