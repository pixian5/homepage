## 一、双浏览器同步 E2E：首次在本机跑通

脚本：`npm run test:sync-e2e`（`scripts/run-browser-sync-e2e.mjs`）。
本轮用**本机临时启动的同步服务**（`127.0.0.1:59387`，独立临时数据文件），
不连接生产服务器、不联网，Chrome 用缓存里的 Chrome for Testing，Firefox 用本机 Developer Edition。

最终通过，两侧断言全为 true：

| 断言 | Chrome A | Firefox B |
|---|---|---|
| unionOk（双方新增都保留） | true | true |
| fieldOk（独立字段编辑都保留） | true | true |
| noOpOk（无变化不重复推送） | true | true |
| futureOk（未来时钟可被本地推进） | true | true |
| tombstoneOk（删除墓碑不复活） | true | true |
| localRestoreOk（本地数据哈希可还原） | true | true |

过程中的 412 重试链路真实发生：

```
add-a-pushed revision=18
add-b-resolved  staleStatus=412 revision=19
edit-a-pushed   revision=20
edit-b-resolved staleStatus=412 revision=21
```

结束后脚本把云端恢复到测试前快照，`cloudRestore.equal = true`。

### 为此修复的 4 个真实问题

1. **忽略命令行扩展加载**：Chrome 137+ 不再认 `--load-extension`，需显式
   `--disable-features=DisableLoadExtensionCommandLineSwitch`，否则扩展根本没装。
2. **无头模式无法直达扩展页**：直接导航 `chrome-extension://...` 会被
   `ERR_BLOCKED_BY_CLIENT` 拦掉。改为安装后由扩展自己 `tabs.create` 打开，与冒烟脚本一致。
3. **Firefox 会话恢复导致 runner 跑两遍**：新 profile 可能恢复崩溃会话，
   补 `browser.startup.page=0` 与关闭 `sessionstore` 恢复。
4. **恢复校验哈希口径错误**：`contentHash` 是对含 `revision` 的整份文档算的，
   服务端每次推送都递增 revision，原实现只删 revision 不删 contentHash，
   于是“恢复成功”被误判失败。归一化哈希改为两者都排除。

## 三、顺带修复的测试基础设施问题

`tests/helpers/browser-process.js` 在进程组信号返回 `EPERM` 时会直接抛错，
导致 Firefox 重启后偶发把整个测试判失败。现在：

- `EPERM` 与 `ESRCH` 一样按“组已不可控”处理，退回只处理直接子进程；
- 父进程已退出时**仍然**要向进程组发信号（浏览器更新重启会把子进程留在原组里）。

## 四、仍未覆盖的部分（明确列出）

1. **周期同步**：按 `syncInterval` 自动触发的定时器没有端到端测试。
2. **冲突弹窗**：`btnConflictMerge/Local/Remote` 三个分支只有内部函数单测，没有点过真实按钮。
3. **同步包导出/导入**：`exportSyncBundle` / `importSyncBundle` 的文件与剪切板路径没走 UI。
4. **Safari 同步**：Safari 的 WebExtension 存储与共享文件方案都没和同步组合验证。
5. **鉴权失败 / 服务器 500 / 磁盘写满**：只有部分单测，缺真实浏览器侧表现。

这些不影响当前结论“核心同步链路可用”，但不能说“所有同步功能都测过了”。
