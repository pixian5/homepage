# 没修改就不该「更新」，更不该重刷壁纸（2026-10-30 19:40）

## 用户的原话

> 我的目标是有修改的话再同步……没修改的话我觉得不必要更新。
> 而且你一更新就刷新壁纸，本来就没变化，为什么非得硬改我的壁纸。

## 根因：轮询每次都走完整合并

`pullNowImpl()` 拿到远端文档后**无条件**调用 `applyRemoteDoc()`：

```js
const remote = await readRemoteSyncDocument();
if (!remote.ok) { ... }
return applyRemoteDoc(remote.doc, deviceId, reason);   // 版本号没变也照样合并
```

`applyRemoteDoc()` 里会跑 `mergeHomepage()`，再比较合并前后的内容指纹：

- 指纹相同 → `applied=false` → 不触发 `onMerged`；
- 但指纹里含 `_syncMeta` 的时钟、placement 的 `updatedBy` 等元数据，
  两边不完全一致时会判成 `applied=true`。

一旦 `applied=true`，就走 `onMerged → render()`，而 `render()` 结尾会
`applyThemeAndDensity()` + `refreshBackgroundIfChanged()`。
背景签名只要有一点点差异（或刷新时序里签名还没落定），就会重新 `loadBackground()`，
而 `loadBackground()` 首尾会加/去 `is-loading` 类——**壁纸就肉眼可见地重刷了一次**。

所以「什么都没改，壁纸却闪一下」不是壁纸模块的错，是**每 5 分钟的轮询把整条渲染链都带起来了**。

## 修法一：版本号没变就根本不合并

`pullNowImpl()` 在拿到远端之后、合并之前加短路：

```js
const prevRevision = Number(_status.lastRemoteRevision) || 0;
const remoteRevision = Number(remote.doc.revision) || 0;
if (prevRevision > 0 && remoteRevision === prevRevision) {
  _status.lastPullAt = Date.now();
  _status.status = "idle";
  _status.lastError = "";
  if (remote.etag) _status.lastRemoteEtag = remote.etag;
  await saveState();
  return { ok: true, merged: false, unchanged: true, reason };
}
```

版本号是服务端唯一的权威计数器，没变就等于「服务端没有任何新内容」，
连 merge 都不必跑，自然也不会 render、不会碰壁纸。

## 修法二：周期同步拿到 unchanged 就结束

`startSyncInterval()` 的回调原本在 `!merged` 时还会再调 `pushNow()`。
加上短路后这条分支会误触发一次多余的推送请求，所以先判断：

```js
if (pull?.unchanged) return;
```

## 回归测试

`tests/sync-engine.test.js` 的 `sync_engine no-op push` 扩充一步：

```js
const mergedBefore = merged.length;
const poll = await pullNow("interval");
assert.equal(poll.unchanged, true);
assert.equal(merged.length, mergedBefore);   // 没有触发 onMerged
```

全量：**251 项全过**；`npm run check` 83 个文件无告警。

## 效果

| 场景 | 之前 | 现在 |
|---|---|---|
| 5 分钟轮询，远端没变 | 完整 merge → 可能 render → 壁纸重刷 | 一次 GET，直接返回，**页面完全不动** |
| 另一台设备真的改了东西 | 合并并渲染 | 合并并渲染（照常） |
| 本机没改动 | 仍会尝试推送 | 内容一致直接跳过（26.5.1） |

## 还要不要轮询？

要。没有轮询就无法知道其它设备改了东西——一次 `GET /v1/sync/state` 只有几百字节。
但现在「没变化」的轮询**不会产生任何界面动作**，只在设置面板的「上次同步」时间上体现。

如果你连这几百字节都不想发，把「同步间隔」改成 **仅手动/变更时** 即可：
那样只有你本机改动、或手动点「立即同步」时才会访问服务器，其它设备的新数据要等下次手动同步才会下来。
