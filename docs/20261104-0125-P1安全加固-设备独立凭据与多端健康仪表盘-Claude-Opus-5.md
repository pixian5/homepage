# P1 安全加固：设备独立凭据、单端注销与多端健康仪表盘（26.7.8）

> 模型：Claude Opus 5 ｜ 日期：2026-11-04 01:25 ｜ 版本：26.7.7 → 26.7.8

## 一、背景与目标

此前三端共用同一个全局 Bearer Token，存在两个问题：

1. **无法精准注销单台设备**——Token 泄露或设备转手时，只能换全局 Token，所有设备一起重新配置；
2. **前端无健康度可视化**——用户看不到有哪些设备在协同、墓碑积压多少、哪些可回收。

本轮落地[全景规划](20261103-2340-项目全景分析与下一步演进路线-Gemini-3.8-Flash.md)中的 P1 安全加固项，实现服务端设备凭据配对/鉴权/退役闭环，与设置面板「协同设备与健康度」仪表盘。

## 二、服务端改造（`scripts/sync-server.mjs`）

### 1. 设备配对 `POST /v1/sync/pair`（仅主管理 Token）

- 鉴权：`Authorization: Bearer <TOKEN>`（未配置 TOKEN 的开放模式放行）；**Device 凭据禁止调用**，防横向提权；
- Body：`{ deviceId: string, deviceName?: string }`，deviceId 必填、≤128 字符，deviceName 默认 `未命名设备`；
- 服务端生成 `deviceSecret = randomBytes(32).toString("hex")`（64 位 hex），只存 `secretHash = sha256(deviceSecret)`，明文仅在本次响应出现一次；
- 记录/更新 `state.devices[deviceId]`：保留 `lastConfirmedRevision`/`lastConfirmedEpoch` 等原有字段，重置 `retiredAt = 0`（重新配对即复活）；原子落盘（临时文件 + rename）；
- **配对可先行**：尚无任何文档时配对会建立「只含设备表、doc 为 null」的占位状态，`loadFromDisk` 与 `GET /v1/sync/state`（对客户端等价 404 no_remote）均已适配。

### 2. 三级鉴权 `checkAuth(req)`

| 凭据 | 格式 | 权限 |
|---|---|---|
| 开放模式 | 未配置 TOKEN | 全部放行（单机开发） |
| 主管理 | `Bearer <TOKEN>` | 读写 + 管理接口（pair/retire/reclaim/devices） |
| 设备独立 | `Device <deviceId>:<deviceSecret>` | 读写（state/confirm），**不能**调管理接口 |

- secretHash 比对使用 `crypto.timingSafeEqual`（常量时间，防时序侧信道）；
- 已退役设备：挂载 `req.authError = "device_retired"`，路由层统一返回 **403** `{ error: "device_retired", deviceId }`；其余失败 401；
- 管理接口（pair / devices / devices/retire / reclaim）新增 `requireMaster` 门禁。

### 3. 防御性修复（实现中发现）

- `withDeviceTouched` 原来会**丢弃** `retiredAt`——退役设备若被任何路径 touch 会意外复活；现同时保留 `deviceName`/`secretHash`/`retiredAt`，常规写入不可能抹掉配对信息或复活退役设备；
- `GET /v1/sync/devices` 输出前浅拷贝并 `delete secretHash`，凭据哈希绝不出网。

### 4. `/health` 扩展

新增 `tombstoneCount`（墓碑总数）与 `reclaimCandidatesCount`（可回收数），前端仪表盘无需另拉设备表即可展示健康度。

## 三、客户端 Transport（`src/js/sync_http_transport.js`）

- `authHeaders(token, deviceAuth)`：`deviceAuth`（或 cfg 本身）携带 `deviceId`+`deviceSecret` 时发送 `Device <id>:<secret>`，否则回退 Bearer——**未配对的旧客户端行为完全不变**；
- 新增 `httpPairDevice` / `httpGetDevices` / `httpRetireDevice` 三个 API；
- `httpPullState`/`httpPushState`/`httpConfirmSyncState` 拦截 403：响应体 `error === "device_retired"` 时返回 `{ ok: false, reason: "device_retired", status: 403 }`，前端可区分「Token 错」与「设备被注销」。

## 四、设置面板仪表盘（`settings-controller.js` + `app-i18n.js` + `styles.css`）

「数据同步」区域内、测试/立即同步按钮下方新增**协同设备与健康度**面板：

- 健康度行：修订 / 代际 / 活跃设备 n/m / 墓碑数 / 可回收数（`/v1/sync/devices` 与 `/health` 并行拉取）；
- 设备清单：状态指示灯（绿=正常、灰=已退役）、设备名、ID 缩写（前 10 位等宽字体）、最后活跃时间、本机标记；
- 非本机且未退役的设备提供**一键注销**按钮（confirm 确认 → `httpRetireDevice` → 刷新清单）；
- 触发时机：点击「测试服务」成功后、立即同步成功后自动刷新，也提供手动刷新按钮；
- 全部纯 DOM 构建（`textContent`），设备名等服务端数据不走 innerHTML；
- 三语（zh-CN/zh-TW/en）17 个新文案 key，其余语言回退 en。

未新增独立模块，`firefox-modules.json` 依赖拓扑无需变更（已验证 Firefox 拼接产物含全部新代码）。

## 五、测试与验证

新增 `tests/sync-device-auth.test.js`（7 项，真实子进程服务端到端）：

1. master Token 配对成功并下发 64 位 hex secret；无/错 Token 配对 401；
2. Device 凭据成功 PUT + GET `/v1/sync/state`；
3. 错误 secret / 未登记设备 → 401；
4. 退役后该设备读写立即 403 `device_retired`（含原始响应体契约断言）；
5. `/v1/sync/devices` 不泄露 `secretHash` 字段名与 secret 明文；
6. `/health` 含 `tombstoneCount`（≥1，推入带 deletedAt 节点制造墓碑）与 `reclaimCandidatesCount`；
7. master Bearer 始终全权（读写/再配对/回收演练），且 Device 凭据调管理接口全部 401。

**验证结果：`npm test` 282/282 通过（原 275 + 新 7），`npm run check` Biome 零告警（顺手修复了上一轮遗留的 1 处 useLiteralKeys info 与本轮 1 处 useOptionalChain warning），三端构建成功，Safari .app 已安装到 /Applications。** 另做了一次 curl 真实冒烟：pair → 404/401 → retire → 403 → health 计数 → devices 无哈希，全链路符合预期。

## 六、遗留与下一步

- 墓碑回收常态化脚本（P1 剩余项）待落地；
- 退役设备在前端的「恢复（retired:false）」入口未做（服务端已支持）。
