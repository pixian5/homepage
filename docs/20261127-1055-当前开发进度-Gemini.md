## 本轮完成内容

### 1. 加固服务端同步协议代际响应头与幂等缓存（`scripts/sync-server.mjs` & `src/js/sync_http_transport.js`）
- **`PUT /v1/sync/state` 代际信息完整性**：在 `200 OK` 与 `412 precondition_failed` 响应中统一补充 `epoch` 字段及 `X-Sync-Epoch` 响应头，并在 `src/js/sync_http_transport.js` `httpPushState` 的 `412` 解析分支同步透出 `epoch`，保证客户端始终能感知最新服务端代际。
- **代际切换失效幂等缓存**：在 `POST /v1/sync/snapshots/restore` 与 `POST /v1/sync/reclaim` 成功提交状态后调用 `idempotency.clear()`，阻止旧 `Idempotency-Key` 延迟重放绕过 `stale_epoch` 栅栏。
- **`readBody` 幂等收敛**：新增 `settled` 状态守卫，防止请求体超限销毁连接后重复触发 `end`/`error`。

### 2. 修复 PWA Service Worker 同源同步 API 缓存风险（`src/sw.js`）
- 将 `CACHE_VERSION` 从 `homepage-pwa-v2` 升至 `homepage-pwa-v3`，激活时自动清理旧版本缓存。
- 在同源 `fetch` 拦截中对 `/v1/`、`/health` 以及携带 `Authorization` 请求头的请求直接透传网络，避免同源反代部署下同步状态接口被 Stale-While-Revalidate 缓存。

### 3. 收紧后台受限协议判定（`src/js/background.js`）
- 将 `RESTRICTED_TAB_URL_RE` 扩展覆盖 `chrome-extension:`、`moz-extension:`、`devtools:` 与 `view-source:`，并导出 `isWebTabUrl`，防止扩展自身页面被误判为普通网页标签。

### 4. 新增回归单元测试
- 扩展 [tests/sync-http.test.js](file:///Users/x/code/homepage/tests/sync-http.test.js)：验证 `PUT` 200/412 `epoch` 返回值，以及快照回滚推进 `epoch` 后重放同 `Idempotency-Key` + 旧 `epoch` 被 `409 stale_epoch` 拦截。
- 扩展 [tests/pwa-manifest-sw.test.js](file:///Users/x/code/homepage/tests/pwa-manifest-sw.test.js)：验证 `v2` 缓存清理以及 `/v1/*`、`/health`、带 `Authorization` 头请求不触发 SW 缓存拦截。
- 扩展 [tests/background-add-bookmark.test.js](file:///Users/x/code/homepage/tests/background-add-bookmark.test.js)：验证 `isWebTabUrl` 对各类扩展/内部/调试协议与正常 HTTP(S) URL 的区分（全量单测增至 **680/680**）。
