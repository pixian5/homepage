# 免费 Apple ID 下 macOS App 与 Safari 扩展的签名设置方案

适用前提：**免费 Apple ID（Apple 账户）**、只在本机使用、不分发不上架。

## 约束（免费账号改不了，只能适应）

| 项目 | 免费 Apple ID 的实际表现 |
|------|--------------------------|
| 签名身份 | `Apple Development`（苹果开发证书），可用，与付费会员一致 |
| 描述文件 | 只能由 Xcode（苹果开发工具）自动管理，**有效期 7 天** |
| 后台手工建 profile | 不可用（需付费会员） |
| App Group（应用组） | 可用，本次已实测拿到带 `application-groups` 的 profile |
| 免签名 / adhoc | **不可行**，详见[免签名与 adhoc 可行性实测](20261008-2046-免签名与adhoc可行性实测-GPT-6.md) |

结论：**签名必须做，唯一要解决的麻烦是 7 天续期。**

## 本次实测出来的关键结论

> **不清本地缓存，Xcode 就不会签发新描述文件。**

连续两次构建验证：

```
第一次：缓存里还有未过期的 profile → 构建成功，但剩余天数 6.96 → 6.96（纹丝不动）
第二次：删掉本项目的缓存 profile    → 构建成功，剩余天数 6.96 → 7.00，UUID 也换了
```

`xcodebuild -allowProvisioningUpdates` 只要看到本地有一份没过期的描述文件就直接复用。
所以「提前续签」如果不清缓存，等于什么都没做。这一点不实测根本发现不了——构建照样 `BUILD SUCCEEDED`。

## 方案：状态检测 + 快速续签 + 每天自动跑

三层结构，各司其职：

```
safari-signing-status.py          只读体检：剩余天数、身份、App Group、是否需要续签
        ↓ needs_refresh
safari-refresh-signing.sh         快速续签：清缓存 → 增量构建 → 重签 → 校验 → 安装
        ↓ launchd 每天两次
setup-safari-signing-refresh.sh   注册/卸载/查看定时任务
```

### 1. 状态检测（只读，随时可跑）

```bash
python3 scripts/safari-signing-status.py            # 人类可读
python3 scripts/safari-signing-status.py --json     # 机器可读
```

输出示例：

```
安装位置 : /Applications/我的首页 Safari.app
版本     : 25.9.3
签名身份 : Apple Development: ibjxk0@gmail.com (YGR8677YMA)
团队标识 : WY97WQFBKC
adhoc    : 否
深度校验 : 通过
描述文件 : Mac Team Provisioning Profile: com.aeroluna.homepage.safari
到期时间 : 2026-10-15T12:03:10Z（剩余 6.96 天）
Xcode 托管: 是
应用组   : 宿主 有 / 扩展 有
Safari   : 未运行

结论     : 状态正常，暂不需要续签
```

退出码：`0` 正常 / `1` 需要续签 / `2` 目标不存在或解析失败。默认剩余不足 **3 天**判定需要续签。

### 2. 快速续签（与完整构建的区别）

```bash
bash scripts/safari-refresh-signing.sh            # 仅在不足阈值时续签
bash scripts/safari-refresh-signing.sh --force    # 无条件续签
bash scripts/safari-refresh-signing.sh --dry-run  # 只构建不安装，用于验证
```

续签**刻意不做**这些事，因为续签不是发布：

- 不递增版本号（完整构建会 bump，续签不会）
- 不重跑 Safari converter（转换器）、不重新生成 Xcode 工程
- 保留 `dist/safari-app/build`，走增量构建，实测约 **11 秒**（完整构建要几分钟）
- 不重配新标签页选择：团队标识与 Bundle ID 都没变，Safari 里的原有选择依然有效
- 不动用户数据、不跑存储快照与回滚

续签**必须做**的事：

- 清本项目在 Xcode 里的 profile 缓存（核心，见上）
- 用 Apple Development 身份由内向外重签（先 `.appex` 再 `.app`）
- 校验宿主 App 与扩展**双方**都带 App Group
- 比对新描述文件的 UUID 与剩余天数，没换新的就**失败退出且不安装**

### 3. 自动续期（每天两次，不打扰）

```bash
bash scripts/setup-safari-signing-refresh.sh install    # 注册 launchd 任务
bash scripts/setup-safari-signing-refresh.sh status     # 查看是否已加载
bash scripts/setup-safari-signing-refresh.sh run-now    # 立即跑一次
bash scripts/setup-safari-signing-refresh.sh logs       # 查看日志
bash scripts/setup-safari-signing-refresh.sh uninstall  # 卸载
```

任务特征：

- Label `com.aeroluna.homepage.safari-signing-refresh`，每天 **09:00 与 21:00** 各一次
- 日志在 `~/Library/Logs/homepage-safari-refresh.{out,err}.log`
- plist 里显式设置 `PATH`——launchd 环境很干净，不设就找不到 `python3`
- **Safari 正在运行就跳过**，下次再试，绝不打断正在用的浏览器
- 剩余天数充足时直接退出，不做无谓构建

已在本机验证：安装 → 状态 loaded → `run-now` 触发 → 日志正常写入 → 卸载/重装幂等。

## 安全约束（设计时就写死，不靠自觉）

1. **先构建后安装**：只有新描述文件校验通过才替换 `/Applications` 里的 App。续签失败时旧版照常可用。
2. **Safari 运行即中止**：构建前拦一次（不白跑），安装前再拦一次（防构建途中用户打开 Safari）。
3. **演练模式不碰安装目录**：`--dry-run` 全程在 `dist/` 里完成，可在任何时候验证。
4. **只删本项目的缓存**：按 `application-identifier` 前缀匹配，不波及其他项目的描述文件。

## 故障排查

| 现象 | 原因与处理 |
|------|-----------|
| `Profile was not renewed (uuid unchanged)` | 缓存没清掉，或 Xcode 账号没登录/没网。先 Xcode → Settings → Accounts 确认登录 |
| `Safari is running; skip` | 正常保护行为，关掉 Safari 后再跑，或等下一个时间点 |
| `profile only has X days left, expected ~7` | 拿到的不是全新描述文件，检查账号状态 |
| `Xcode project not found` | 没生成过工程，先完整跑一次 `scripts/build-macos.command` |
| 扩展突然失效 | 先看 `safari-signing-status.py`，大概率描述文件过期；手动 `bash scripts/safari-refresh-signing.sh --force` |

## 若日后升级为付费会员

付费会员可以在开发者后台手工创建有效期 1 年的 macOS App Development 描述文件，
配合 Manual signing（手动签名）即可一年不用管，届时本自动续期任务可以直接 `uninstall`。
