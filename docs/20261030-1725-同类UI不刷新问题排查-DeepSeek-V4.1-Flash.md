# 同类问题排查：还有哪些设置「同步过来了但页面不生效」（2026-10-30 17:25）

## 排查方法

把所有「整包替换 `data`」的入口列出来，再对照哪些设置是**副作用型**（直接改 CSS 变量 / DOM 属性，
不经过 `render()`），看替换后有没有人重新应用。

## 结论：一共 6 条替换路径，3 个设置项会漏

### 整包替换 data 的入口

| # | 入口 | 位置 |
|---|---|---|
| 1 | 初始化 | `app.js` init |
| 2 | 跨标签页 / popup 外部写入后重载 | `reloadFromStorage()` |
| 3 | 同步合并成功 | 同步引擎 `onMerged` 回调 |
| 4 | 导入（剪贴板 / 文件 / 合并） | `settings-controller.js` 两处 `setData` |
| 5 | 恢复备份 | `settings-controller.js` 恢复按钮 |
| 6 | 清空数据 | `settings-controller.js` 重置为 `defaultData()` |

### 设置项盘点

| 设置 | 应用方式 | 原来会被上述路径刷新吗 |
|---|---|---|
| 书签、分组、文件夹、排序 | `renderGroups()` / `renderGrid()` | ✅ 是 |
| 语言 | `applyStaticI18n()`（在 `render()` 里） | ✅ 是 |
| 侧边栏隐藏 / 收起 | `applySidebarState()`（在 `render()` 里） | ✅ 是 |
| 显示搜索框 / 空态提示 / 批量按钮 | `render()` 内联 | ✅ 是 |
| 固定列数 | `render()` 用 `gridTemplateColumns` | ✅ 是 |
| **背景（含遮罩强度）** | `loadBackground()` + `applyBackgroundOverlay()` | ❌ **26.4.6 已修** |
| **主题（浅色/深色/跟随系统）** | `applyTheme()` | ❌ **26.4.7 修** |
| **卡片密度 / 字号** | `applyDensity()`（`--grid-gap` / `--tile-font` / `--base-font`） | ❌ **26.4.7 修** |

也就是说：用户遇到的「背景要手动切一次」，**主题和密度是两个没被发现的同款问题**——
在另一台设备改主题或卡片间距/字号，同步过来后页面不会变，同样要手动去设置里碰一下才生效。
导入备份、恢复备份、清空数据之后同理（导入的包带着主题/背景，却没被应用）。

## 修法：统一收口到 render()

不再在每条路径各补一行（容易再漏），而是把「副作用型设置」的应用放进 `render()` 末尾：

```js
function render() {
  ...
  updateOpenModeButton();
  applyThemeAndDensity();        // 主题 + 密度/字号（便宜，几行 style 写入）
  void refreshBackgroundIfChanged();  // 背景：先比签名，变了才真正去取图
}
```

- `applyThemeAndDensity()` = `applyTheme()` + `applyDensity()`，纯 CSS 变量/属性写入，重复调用无副作用。
- 背景最贵（每日 Bing 要发网络请求、还有 toast），所以仍保留 26.4.6 的签名比较，
  设置没变就不重跑。
- 6 条替换路径最终都会调用 `render()`，因此全部自动覆盖；
  以后新增类似设置，只要接进这两个函数即可，不用再改六处。

## 验证

- `node --test`：250 项全过
- `npm run check`：83 个文件无告警
- 构建 26.4.6 → **26.4.7** 通过，`dist/chrome/js/app.js` 内含 `applyThemeAndDensity`

## 遗留建议（未做）

`render()` 现在承担了「渲染 + 副作用设置应用」两件事，名字有点名不副实。
后续可以拆成 `render()` + `applyViewSettings()`，由调用方统一 `renderAndApply()`；
不过这属于重构，不影响当前行为，先记在这里。
