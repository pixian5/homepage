# 27.2.7：修复 `saveData` 配额裁剪原子性与 Safari 稳定存储同步遗漏

## 问题与实现

1. **修复 `src/js/storage.js` 中 `saveData()` 配额裁剪破坏内存与遗漏 Safari 同步**：
   - 将 `lastUpdated` 推进改为 `Math.max(nowTs(), (Number(prevLastUpdated) || 0) + 1)`，防止本地时间偶发落后时时间戳倒退，并在所有写盘失败路径统一回滚 `lastUpdated = prevLastUpdated`。
   - 将配额超限后的三级降级（`trimLocalBackups` → `trimLocalUploadIcons` → `trimLocalBackground`）改为表驱动，全部先在 `deepClone(data)` 克隆副本上逐级裁剪与试写：
     - 仅当某一级试写成功时，才把对应层级的裁剪结果写回原 `data` 对象，并补全调用 `await writeSafariStableHomepage(data, api)` 同步 Safari 稳定存储后返回对应哨兵字符串（`"local_trimmed_backups"` / `"local_trimmed_icons"` / `"local_trimmed_background"`）；
     - 若三级试写仍全部遇到配额错误，保持内存中的 `data.lastUpdated`、`data.backups`、用户上传图标与自定义背景完整无损。
