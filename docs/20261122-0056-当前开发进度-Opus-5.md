# 27.1.9：导入写盘失败不再误报成功

## 问题与实现

JSON 覆盖、合并、仅新增、批量网址、标准 HTML 书签，以及同步包文件/剪切板入口，原先直接修改运行中的数据并忽略 `persistData()` 返回的 `{ok:false}`，写盘失败仍可能关闭面板、刷新界面和提示成功。

现在各入口统一通过实例内 `commitImport()`：先复制当前数据，在候选副本执行备份与修改；只有保存返回 `ok:true` 才走成功提示和界面刷新。返回失败或抛异常时恢复原对象引用、备份基线、设置与放置时钟基线，并将错误交给入口的失败提示。批量网址也补上异常捕获。设置导入错误信息不再一律让用户去其它浏览器重新导出，而是直接显示真实原因。同一控制器中的并发导入会被拒绝，失败释放标记后允许重试。

这不是跨标签页事务或文件系统断电恢复协议；正常编辑与同步并发、存储写入部分成功等场景，不能仅凭本轮模拟测试宣称已经覆盖。

## 验证

- 七种入口 × 两种故障（返回失败/抛异常）：14 条新增回归测试。修复前全部失败，修复后全部通过。
- 检查原对象及书签、分组、备份不被污染；模拟持久化中追加时钟字段后失败，也不泄漏到原对象。
- 失败不关闭面板、不渲染、不启动图标抓取、不提示成功；同一面板重试成功后才检查写入内容、渲染和成功反馈。
- 备份恢复已有失败测试继续通过。本轮全量测试 568/568，静态检查通过。
- 通过 dist 入口只生成四份 27.1.9 归档，检查版本与模块内容一致、Firefox 经典脚本语法通过。已安装 Safari 宿主仍是 27.1.7，签名摘要未变；没有运行安装、新建/关闭窗口、浏览器启动或真实浏览器交互测试，也未修改日常书签和常驻服务。
