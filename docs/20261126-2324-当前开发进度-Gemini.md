# 27.3.0：统一 `background.js` 跨端调用与串行写入，并补齐双端按需注入真实冒烟闭环

## 问题与实现

1. **统一 `src/js/background.js` 跨端 API 调用、写串行化与错误消费**：
   - 接入 `shared-utils.js` 导出的 `getChromeApi` 与 `callExtensionApi`，替代直接硬编码的 `chrome.storage` / `chrome.tabs` 回调分支，使 `homepage_add_bookmark_to_folder`、`homepage_open_bookmark` 及标签页查询（`queryActiveTab` / `queryWebTabById`）同时兼容 Chrome 回调（并正确消费 `runtime.lastError`）与 Firefox / Safari Promise-only 运行时；
   - 抽离共享 `isWebTabUrl` / `isWebTab` 过滤逻辑，并通过 `serializeBookmarkWrite` 串行化后台保存请求，消除连续点击侧栏「添加书签」时的存储读改写竞态；
   - 在 `tests/background-add-bookmark.test.js` 新增运行期 `onMessage` 回归用例，验证 Promise-only 并发添加书签串行落盘与 Chrome `tabs.create` `lastError` 错误收敛。
2. **补齐真实浏览器「按需动态注入 Toast + 书签侧栏 + 后台写盘」端到端冒烟**：
   - 在 `src/popup.js` 为自动 `init()` 增加 `#popupBookmarkList` 存在性守卫，支持在扩展测试页中直接复用并验证真实的 `showToastInTab` / `openBookmarkSidebar`；
   - 在 `scripts/run-browser-smoke.mjs` 增加本地 HTTP 网页路由 `/smoke-page.html`，并在 `tests/browser-smoke/runner.js` 实测：对未静态预注入 `content_scripts` 的真实 HTTP 标签页按需连续两次注入 `content-toast.js`（校验 IIFE 二次注入幂等）、按需注入 `bookmark-sidebar.js`（校验单侧渲染、点击目录经后台脚本写入并实时刷新侧栏列表、刷新后数据保留及 `Escape` 关闭）。
