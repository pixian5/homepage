# 壁纸全链路隐患排查与 SWR 渐变加固

> 日期：2026-11-07 08:50

## 1. 背景与排查目标

在第 29.2 轮（commit `2eb405d`）中，我们全链路根除了 Chrome 打开新标签页背景回退纯色（`schemaVersion: 1` 诱发 `MIGRATIONS[1]` 重置壁纸）的致命缺陷。在此基础上，用户要求深入排查：“分析还有其它问题吗？”

我们针对背景渲染、Bing 壁纸获取与生命周期、自定义背景图持久化、多端数据同步合并等全链路展开了深度排查，发现了 5 个潜伏在边缘场景、性能体验和网络波动中的隐蔽问题，并逐一进行了工程级加固与测试验证。

---

## 2. 潜伏问题深度剖析

### 问题 1：Bing 壁纸缓存缺少语言字段，切换语言后不更新

- **现象**：用户在设置中将语言从 `zh-CN` 切换为 `en` 或其他语言后，新标签页壁纸依然显示原语言区域的 Bing 壁纸，直到第二天跨日。
- **根因**：
  - `src/js/theme-manager.js` 中 `backgroundSignature` 函数已明确将 `s.language` 作为签名比对要素：
    ```javascript
    s.backgroundType === "bing" ? `${s.backgroundType}:${s.language || ""}` : ...
    ```
  - 但底层 `src/js/bing-wallpaper.js` 中的缓存对象仅保存了 `{ date, url, dataUrl, ts }`，未记录缓存当时的 `language`。
  - 在 `getBingWallpaper` 的新鲜度判断逻辑中，只要 `date === key` 或 `now - ts < CACHE_TTL_MS`，便直接命中缓存返回，完全忽略了语言维度的变更。
- **影响**：多语言切换后背景壁纸脱节，无法按用户预期获取当地的 Bing 每日壁纸。

---

### 问题 2：缺乏 Stale-While-Revalidate（SWR），隔日打开新标签页长时间卡在纯色

- **现象**：经过一天或缓存过期（>6小时）后，用户点击打开新标签页时，首屏会出现长达数秒甚至十几秒的底色等待（暗黑背景 `#0b0f14`），壁纸迟迟无法呈现。
- **根因**：
  - `theme-manager.js` 在加载 Bing 壁纸时，给背景容器加了 `is-loading` class（透明度降至 0.4），露出 `body` 纯色。
  - 随后 `await deps.getBingWallpaper(settings.language)` 会阻塞等待网络请求。
  - 由于 Bing 壁纸 API 和大图下载通常需要 500ms ~ 3s（甚至在网络弱时触发 15s/20s 超时），在此期间页面一直处于等待态，用户看到的就是纯色背景。
  - 实际上本地已经缓存了昨天的旧高清壁纸，完全可以直接瞬时展示。
- **影响**：每次隔天首开新标签页都会产生明显的卡顿感与纯色落差，严重影响用户体验。

---

### 问题 3：现代 CSS 渐变嵌套函数（如 `rgba`）被正则误杀回退纯色

- **现象**：当设置渐变背景为现代主流语法（例如带透明度的配色：`linear-gradient(120deg, rgba(29, 42, 59, 0.8), #0b0f14)`）时，背景直接变为空白/纯色。
- **根因**：
  - `theme-manager.js` 中校验 CSS 函数的正则为：
    ```javascript
    /^[a-zA-Z-]+\([^)]*\)$/.test(style)
    ```
  - 该正则内部使用了 `[^)]*`（非右括号），当解析到 `rgba(29, 42, 59, 0.8)` 的第一个右括号 `)` 时就终止了内部匹配，导致整个长串无法匹配结尾的 `$`，正则判定为非法样式，直接放弃设置并回退底色。
- **影响**：阻断了所有合法且美观的现代复合渐变语法。

---

### 问题 4：设置面板“合并导入（merge）”误清空自定义壁纸

- **现象**：用户在设置中选择“合并导入（merge）”备份数据时，若原备份中含有自定义大图壁纸，合并后壁纸被清空回退。
- **根因**：
  - `settings-controller.js` 的 `handleImport` 流程中，合并导入时复用了 `toSyncDocument` 生成基线文档。
  - 为防止同步流量爆炸，`toSyncDocument` 中设计了 `settings.backgroundCustom = ""`（大图不入云）。
  - 但本地文件导入本质是用户完全信任的本地行为，不应被云端同步的投影裁剪逻辑误伤。
- **影响**：合并导入操作会导致用户珍藏的本地自定义大图丢失。

---

### 问题 5：存储超限降级 `trimLocalBackground` 导致裂脑态

- **现象**：在极端存储空间告警、触发 `trimLocalBackground` 裁剪自定义壁纸时，新标签页每次启动都会反复寻找大图失败。
- **根因**：
  - `trimLocalBackground(data)` 仅执行了：
    ```javascript
    data.settings.backgroundCustom = "";
    ```
  - 但没有把 `data.settings.backgroundType` 从 `"custom"` 改回 `"color"`。
  - 这导致系统处于 `backgroundType === "custom"` 但大图却为 `""` 的裂脑状态。
- **影响**：启动时每次都会进入自定义壁纸加载逻辑，判定为空后再回退，造成逻辑冗余和状态不一致。

## 3. 落地修复与加固方案

### 3.1 Bing 壁纸语言隔离与 Stale-While-Revalidate（SWR）

在 `src/js/bing-wallpaper.js` 中：
1. **语言隔离**：将缓存格式扩展为 `{ date, language, url, dataUrl, ts }`。新鲜度校验必须同时满足 `cache.language === normalizedLang`，语言不一致立即重算。
2. **SWR 机制**：支持传入 `options.onUpdated` 回调。
   - 若本地存在旧壁纸（即使过期或语言不同），**0ms 瞬时返回旧壁纸**（`fromCache: true, stale: true`）；
   - 在后台发起无阻塞静默更新 `fetchAndSaveBingWallpaper`；
   - 静默下载成功且发现新壁纸后，触发 `onUpdated(fresh)`，`theme-manager.js` 平滑替换背景，用户感受不到任何网络等待。

### 3.2 现代 CSS 渐变语法安全放行与防注入

在 `src/js/theme-manager.js` 中引入专用的 `isSafeCssGradient(style)` 函数：
```javascript
function isSafeCssGradient(style) {
  if (typeof style !== "string") return false;
  const s = style.trim();
  // 必须是渐变函数开头并闭合
  if (!/^(?:(?:repeating-)?(?:linear|radial|conic)-gradient)\(.*\)$/s.test(s)) return false;
  // 严厉禁止注入攻击：分号、括号闭合后注入花括号、url() 引用、javascript: 等
  if (/[;{}<>]|url\s*\(|javascript\s*:/i.test(s)) return false;
  return true;
}
```
放行合法的嵌套 `rgba(...)`/`hsl(...)` 语法，同时严密阻断 XSS 和 CSS 样式逃逸注入。

### 3.3 合并导入保全与配额清理防裂脑

1. `src/js/settings-controller.js`：合并导入逻辑补充大图保全：
   ```javascript
   if (repairedIncoming?.settings?.backgroundCustom && !merged.state.settings?.backgroundCustom) {
     merged.state.settings.backgroundCustom = repairedIncoming.settings.backgroundCustom;
   }
   ```
2. `src/js/storage.js`：`trimLocalBackground` 在清空大图的同时，规整 `data.settings.backgroundType = "color"`，消除裂脑态。
